## 二、逐条说明

### ① 天道攻城死锁 —— 已修

**审查说得对**：`besiege` 强制要求目标城已有驻军，而 LLM 的动作集里没有 `march`。
天道每次说"打某城"，引擎都回"该城没有你的兵"。

**修法（两层，不是只改一处）**：

```js
// strategy.js：天道说"打这座城"，兵却不在，引擎替他把兵派过去
if (troopsAt(world, f, target) < 1) {
  const from = 驻军最多的那座城;
  const mv = march(world, fid, from, target, 派八成兵);
  r = mv.ok ? `${f.name}自${from}发兵，${mv.days}日可至${target}` : 失败原因;
} else {
  r = besiege(...);   // 兵已在城下，才真打
}
```

```diff
- action: recruit|buy_grain|besiege|bribe|fortify|hold
+ action: recruit|buy_grain|march|besiege|bribe|fortify|hold
```

**同时保留的约束**：行军仍要过路（同道/关隘/关系），粮不够仍然发不出去。
**所以"自动"只是把命令翻译成合法动作，不是替他作弊。**

### ② 幽灵领地 —— 已修，并实测复现过

**这是真 bug，我认，而且我实测抓到过：**

```
破城前：朝廷 55 城、王家 1 城
破城后（修复前）：王家 +1，但朝廷没减 → 同一座城两家都声称拥有
```

**修法：唯一写入口 `changeCityOwner(world, cityName, newOwnerFid)`**

```
① 旧主 cities 里剔除该城
② ct.owner 改新主
③ 新主 cities 里补入
④ 城里驻着旧主的兵 → 兵随城转归新主（免得兵城分离）
```

**破城、招降、枭雄自立三处全部改走它。**
**实测（修复后）**：

```
破城前：朝廷 55、王家 1
破城后：朝廷 54、王家 2
抽查：朝廷 still 含苏州府 = False；王家含苏州府 = True
```

### ③ 一维数组伪装邻接 —— 已修

**审查举的例子是准的**：按 `i±1` 判定时，江南道的邻居只有京畿道，
要去淮南、闽浙、江西全部"路不通"；岭南和剑南成了邻居。

**修法**：写死一张 17 道的接壤表（`REGION_ADJACENCY`），并自动双向承认。

```
江南道 → 淮南道、淮北道、闽浙道、江西道、荆湖道
淮南道 → 江南道、淮北道、河南道、京畿道
岭南道 → 闽浙道、江西道、荆湖道、云贵道
剑南道 → 陇右道、云贵道、荆湖道、关内道
闽浙道 → 江南道、江西道、岭南道
```

**这张表仍是"人写的近似"**，不是 GIS 数据；但比数组下标正确，而且以后可以整体替换成数据文件（审查建议的方向）。

### ④ 推演双跑 —— 已修

**审查说得对**：第 7 日，时钟跑规则推演、server 跑 LLM 推演，同一天两套齐发。

**修法**：

```js
// server：决定用 LLM 时，先打标记
w0.flags.strategyByLLM = true;

// clock：看见标记就只兜底，不重跑
if (day % 7 === 0 && !world.flags?.strategyByLLM) npcStrategyTurn(...);
```

**语义变成**：LLM 是主力，规则推演是"没有天道时"的降级通道，**不再同日双跑**。

> 补充一句：标记是"当日"语义，第二天不会残留（`strategyByLLM` 只在这一轮置位；
> 若要更严格，可改成 `strategyDay = day` 比对，下一轮我可以顺手换成这个写法）。

### ⑤ 攻城战损 —— 已改，但我加了随机

**审查建议生还率 40%~50%。我改成 45%~60% 随机**：

```diff
- (win ? Math.round(send * 0.75) : 0)
+ (win ? Math.round(send * (0.45 + Math.random() * 0.15)) : 0)
```

**理由**：固定值会让"攻城"变成一道可计算题；**随机区间保留了战场的不确定**，
但整体已经从"破城只折两成半"降到"折四到五成半"，滚雪球会明显变慢。

**如果你要更狠（比如 30%~45%），改一个常数就行。**
