# FamilySoul 维护手册（AI 必读）

> 目的：避免"改 A 崩 B"。每次改动前先看这里，改动后按「验证清单」跑一遍。
> 这份文档由历次踩坑总结而来，**每一条都对应一个真实事故**。

## 二、绝对不能破坏的机制

### 1. 位置只有一个主人（优先级铁律）
```
① 引擎识别到动作（去/找/叫/派/走了）  → 引擎搬，模型无权改
② 引擎没识别到，模型写了 【天道·地点·X】 → 采纳模型的
③ 都没有                              → 位置不变
```
- 实现在 `pet-service.js` 的 `engineMovedHusband` + `syncSceneFromReply({skipHusbandMove})`
- **改动风险**：若让模型优先，会出现"说走了人没走""刚派出去就被日程拉回"

### 2. 方括号 `【】` 是角色名专用
- `【正妻·婉儿】：` 是分角标签
- `【天道·地点·雅阁】` 是场景标记，**绝不能改写成圆括号**（会废掉转场）
- 动作/旁白一律圆括号 `（）`
- 实现在 `pet-service.js` 的「方括号改圆括号」块，**已对 `天道` 开头豁免**

### 3. 在场过滤只认「真有人名」
- `enforcePresence()` 会把**不在场的人**的段落删掉
- 但**必须先判断这个名字是不是账本里真有的人**（`_knownNames` 白名单）
- **事故**：曾把 `【压着声道，这才扬声应门外】` 当人名删掉，只剩空标签

### 4. 两条完全隔离的对话路径

| | 相公号（husband） | 绑定成员的号（如 liuwenxia） |
|---|---|---|
| 触发条件 | `actorId` 为空 | 成员配置里有 `actor` |
| AI 演谁 | 婉儿/芸娘等角色 | **王甯（相公本人）** |
| 人格来源 | `roles/*.md` | 代码内置的王甯卡 |
| 天机 | 全知视角 | 王甯视角（她看不到你的银钱/势力/别的女人） |
| 标签 | 角色名 | `【王甯】` |

**硬性要求**：
- `_viewerActorId` 必须在每次 `chat()` 开头重置
- 绑定成员分支必须在 `buildSystemPrompt` **最前面 return**，不得拼接相公/婉儿那一整套（1.5 万字）规则
- 王甯**禁止自称"妾身/奴家"**（提示词已写死）

### 5. 天机分两种视角
```js
buildStateSummary(dir, { roleName, memberKey, viewer })
// viewer = null        → 全知（相公）
// viewer = 'liuwenxia' → 该人物自己的视角（不泄露别人的隐私）
```

### 6. 版本迁移：磁盘数据会覆盖代码
`loadState` 里 `{...base, ...raw}`，**raw 优先**。所以改预设人物（日程/住处/性别）必须：
1. 提高 `stateVersion`
2. 在迁移块里把新值刷进 `mergedActors`
3. **返回对象里 `stateVersion` 要写在 `...raw` 之后**（否则每次都重复迁移）

## 三、已修问题清单（含根因，别再犯）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 婉儿死活不认芸娘 | 11 月单数月 → 自动切"现代一夫一妻" | 默认定居古代，取消按月轮转 |
| 2 | 同上 | 账本里记着"迎娶芸娘"假承诺 | 账本消毒 + 写入闸门 |
| 3 | 同上 | 提示词把"芸娘"列进"待娶名单" | 排除府中人体 |
| 4 | 同上 | 历史里有"她是哪家姑娘"的错话 | 上下文过滤 |
| 5 | 她忘了大被同眠 | 只喂最近 8 条对话 | 长期记忆 `world.memories` + 【旧事】 |
| 6 | 全府挤进"马车" | 场景同步把所有说话人都搬过去 | 过场地点只挪相公；最多带 2 人 |
| 7 | 提到的人凭空出现 | 模型戏剧本能 | ①在场铁律置顶 ②硬性掐掉不在场段落 |
| 8 | 她说"下楼招呼客人"（在别人家） | 分不清自己铺子与所在地 | 天机加【各自的去处】 |
| 9 | 说了"走了"人没走 | 引擎只处理相公移动 | `applyNpcDeparture()` |
| 10 | 派出去的人秒回 | 日程把她拉回 | `away.untilDay` 外派豁免 |
| 11 | 约定过期就消失 | 一次性约定 | 支持 `every` 周期 + 失约扣怨怼 |
| 12 | 怨怼只涨不消 | 没有衰减 | 每日 -1、亲密 -6 |
| 13 | 睡过还"到此为止" | 关系值跟不上剧情 | 亲密自动结算 +8/+5 并标相好 |
| 14 | 自己的妻妾也拒绝 | 态度阶梯对外人设计 | `household` 豁免拒绝档 |
| 15 | 气泡连发三条 | 同一人多段重复标签 | `mergeSameSpeaker()` |
| 16 | 不滚到底 | 回复替换占位气泡，条数不变 | 内容签名判断（客户端） |
| 17 | 显示"离线中" | 一次健康检查失败就判离线 | 连续 2 次才判 + 检查重试 |
| 18 | 发消息卡住 | 连接握手失败等 60 秒 | 连接超时 8 秒 + 自动重试 3 次 |
| 19 | 动作方括号看着乱 | `【】` 被拿来写动作 | 非人名方括号改圆括号 |
| 20 | 王甯自称"妾身" | 历史被旧回复污染 + 没强调性别 | 清历史 + 性别硬规矩 |

## 四、改动前后必须跑的验证

### 改完必跑（语法 + 冒烟）
```bash
node --check src/pet-service.js
node --check src/server.js
node scripts/build-update.mjs
```

### 动了对话链路 → 端到端双账号回归
用**假模型**跑真引擎（`PET_SERVICE` 注入 stub `llmClient`），至少验证：
1. 相公号：回复标签是角色名、场景标记保留、转场生效
2. 绑定号：AI 演王甯、标签是王甯、不泄露银钱/势力
3. 位置：`去X` / `找X` / `叫X过来` / `派X去Y` / `走了` 五种动作

### 动了世界数据 → 体检 + 自愈
```bash
node scripts/audit-world.mjs   # 60 天模拟 + 不变量检查，应为 0 问题
```

### 部署后确认版本
```bash
curl http://192.168.1.254:3088/health
# features 应包含最新改动对应的标记
```

## 六、常见陷阱

1. **PowerShell 批量替换会命中多处**
   必须先用 `Select-String` 确认命中行数，再用 `edit` 工具或递增的 anchor。
   事故：一次 `.Replace` 把 ritual 分支插进了 `buildSystemPrompt`，导致所有请求 500。

2. **`a.b?.c` 在 PowerShell 里会被当成变量**
   写 JS 代码用 `@' ... '@` 单引号 here-string，或直接用 `edit` 工具。

3. **`Number(x) || 默认值` 会把 0 当空**
   要保留 0 必须用 `Number.isFinite(Number(x)) ? Number(x) : 默认`。

4. **`includes('')` 永远为 true**
   匹配名字时必须先判空。

5. **世界日期/农历一律走 `worldDate(world)`**
   不要自己算，也不许让模型编（天机里已给公历+农历）。

6. **不要给成员配 `role: '傲娇助手'`**
   绑定成员会因此吃到婉儿那套规则。绑定成员的 `role` 不再起作用（走 `actor` 分支）。

## 七、发布流程

```bash
node scripts/build-update.mjs        # 生成 update.tar.gz
git add -A && git commit -m "..." && git push origin main
```

部署（唯一正确目录 `/opt/familysoul`，禁止提 `/opt/surfcore-server`）：
```bash
cd /opt/familysoul && wget -O - http://192.168.1.112:8089/update.tar.gz | tar -xz && chmod +x *.sh && ./stop.sh && ./start.sh
```

客户端改动必须走完整闭环：
`flutter analyze` 零告警 → 本地构建 APK → 推送 iOS Actions → 产物同步桌面 + 共享目录。
