## 二、阻断级问题（P0）

### P0-1 助手鉴权兜底 → 任何无效 token 都会变成"相公"

```js
// src/server.js（assistant chat / history / clear 三处都是这个写法）
const member = resolveMember(req, url);
const memberKey = member?.memberKey || 'husband';   // ← 破口
```

**后果**：
① 拿一个乱填的 token 调 `/api/assistant/chat`，**用的是相公的助手历史**；
② 还能 `POST /api/assistant/clear` **把相公的助手记录清空**；
③ 隔离做了九成，被这一行拆掉最外层门锁。

**修法**：三个助手接口开头加 `if (!member) return sendJson(res, 401, { ok:false, error:'通行令牌无效' })`。

---

### P0-2 天道不认识新来的人

`user-registry.js` 建了角色、写了 `humanBound: true`，**但没有任何一处把"城里来了个新人"告诉天道**。

**后果**：
新玩家进世界第一句话，天道对他的认知是空的——**要么当空气，要么当路人乱编**，"天道第一次见他，要认这个人"落空。

**修法（两处，都不难）**：
```
① 建角成功时写一条世界事件：新面孔入城（姓名/年岁/来处/落脚处）
② 给天道注入一次性事实块：新面孔是谁、从哪来、性情如何、住在哪
   ——只注入一次，之后靠世界记忆
```

## 三、内测发号：现在的缺口（不上外网也要解决）

既然不走公开注册，**朋友的角色是怎么进世界的？** 目前代码里有两条路，都不完整：

| 路径 | 现状 | 缺什么 |
|---|---|---|
| `POST /api/register` | 能建号、发 token | 没有邀请码/限流（内测可接受） |
| 管理端手工建角色 | 有 `/api/admin/actor/set` 可改属性，但没有"建人 + 发 token"的一步到位接口 | 需要手工拼：先建 actor，再改 config 绑 token |

**建议（内测最小闭环）**：
```
一个内部发号接口：输入 姓名/性别/年龄/城池/性情 → 返回一次 token
（背后就是 register 那套逻辑，但不暴露给外网、不需要邀请码）
```
**这样你给朋友发一条 token，他填进 App 就能进世界**，不用你手改 config。

## 四、中等（P1）

### P1-3 新角色凭空与相公有了 40 信任

```js
relations: { husband: { trust: 40, desire: 0, fear: 0, grievance: 0 } }
```

**一个刚进城的陌生人，对王甯的信任是 40**（高于不少老 NPC）。天道会照这个演——"素不相识"变"半熟"，人设第一句就歪。

**修法**：新角色关系清零（0~10 起步），由交往长出来。

### P1-4 所有新角色共用一个客栈当"家"

```js
home: 'inn'
```

**后果**：看板上"谁住哪"全挤一处；天道会认为他们同居；以后成家置产全乱。
**修法**：一人一座小院（按城池分配，哪怕名字叫"某某的小院"）。

### P1-5 助手历史与注册用户表**不在备份里**

`scripts/backup.mjs` 只备份 `world/state.json`、`world/milestones.json`、`data/chat/**`。

**`data/assistant/` 与 `data/users.json` 都没备份** → 机器一坏，**助手对话和已发出去的账号全没**。内测期间尤其致命（朋友的号丢了得重建）。

**修法**：备份清单加这两项（`--prune` 逻辑照旧）。

### P1-6 助手成本没有单独计数

世界与助手共用一套 token 消耗，账单混在一起。**内测几个人还能扛，人一多就算不清谁在烧钱。**

**修法**：助手单独累计（按账号），世界另记一份。
