## 三、阻断级问题（P0，必须改）

### P0-1 助手鉴权兜底 → 任何无效 token 都会变成"相公"

```js
// src/server.js
const member = resolveMember(req, url);
const memberKey = member?.memberKey || 'husband';   // ← 这里
```

**后果**：拿一个乱填的 token 调 `/api/assistant/chat`，就会用**相公的助手历史**，还能读写、清空它。
**等于把"隔离"最外层的门锁拆了。**

**正确做法**：`if (!member) return 401`。三个助手接口（chat / history / clear）都要加。

---

### P0-2 注册没有邀请码校验

需求是硬性的（"暂时需要！后期可以加防御"），现在是裸接口：

```js
const resData = userRegistry.register(body);   // body 里根本没有 invite
```

**后果**：
① 谁都能批量注册，往世界里灌角色；
② 你定的"后期加防御"失去抓手（没有码可管）。

**正确做法**：邀请码独立表（`data/invites.json`），一次性或限额；注册前校验、成功后标记已用。

---

### P0-3 天道不认识新来的人

`user-registry.js` 建了角色、写了 `humanBound`，但**没有任何一处告诉天道"城里来了个新人"**。

**后果**：新玩家进世界第一句话，天道完全不知道他是谁——**要么当空气，要么当路人乱编**。这正是你说的"天道第一次见他，要认这个人"。

**正确做法**：建角成功后写一条事件 + 在天道的事实区注入一次"新面孔：某某，某岁，从某城来，性某，住在某处"。**注入一次即可，之后靠世界记忆。**

---

### P0-4 新角色凭空与相公有了 40 信任

```js
relations: { husband: { trust: 40, desire: 0, fear: 0, grievance: 0 } }
```

**后果**：一个刚进城的陌生人，对王甯的信任是 40（比很多老 NPC 还高），天道会按这个演——**"素不相识"变"半熟"**，人设直接歪。

**正确做法**：新玩家出生时关系为**空/极低**（trust 0~10），由后续交往长出来。

## 四、中等（P1）

### P1-5 所有新玩家共用一间客栈当"家"

`home: 'inn'`。**一个民宅应该一人一座**（哪怕小院），否则：
① 世界看板上"谁住哪"全挤在一处；
② 天道会认为他们同居；
③ 以后成家、置产全部混乱。

### P1-6 姓名校验借用了"地名规则"

```js
const placeCheck = isPlaceName(rawName);
if (placeCheck.ok && placeCheck.looksLikePlace) return '地名不可作为人物姓名';
```

`isPlaceName` 是给地点用的（要求 2~6 字、不能方位词开头、不能动词开头）。**拿去判人名会误伤**：比如"高升""金榜"这类名字会被动词/方位规则波及。

**正确做法**：人名有自己的规则（2~4 字、不含疑问/地名后缀、不与既有角色重名、做归一化去空格）。**两套规则分开，别互相借。**

### P1-7 注册接口无限流

同 IP 可无限提交。**至少要：同 IP 每分钟 ≤3 次 + 同姓名并发拒绝。**

### P1-8 一人一角色没有拦截

同一账号再进注册页仍可再建。

### P1-9 新角色没有"来处/性情"落账

`origin` 只写进了 `role` 字符串（"初入临江的布衣"），**不是结构化字段**。以后想做"苏州来的人对茶行更熟"这类设定，就没有数据可用。

### P1-10 事件流里没有"入城"记录

新角色进世界是一个**世界级事件**，现在完全没写。看板、自检、天道记忆都看不到。
