## 2. 待办（按顺序做）

### P0 · 会出戏 / 会坏数据（先做这 3 件）

| # | 问题 | 改法 | 验收 |
|---|---|---|---|
| 1 | 新娶媳妇 `home = 'warm_pavilion'`（不存在的地点） | 改成 `backyard` | 娶人后位置可用 |
| 2 | 同行名单不持久（`world.party` 没有） | `world.party = { husband: ['liuwenxia'] }`，靠"带上X/你留下"增删 | 说"去客栈"后再说"去街上"，她仍跟着 |
| 3 | 说"去不存在的人家"退化成闲聊 | 命中不到人 → 造一处或明说"没这户人家" | 说"去苏娘家"必有落点 |

### P1 · 看板（现在完全看不见世界）

**接口补 4 个字段**（`GET /api/admin/world`）：


**加 4 张卡，顺序如下：**

| 卡 | 顶部一行 | 明细 |
|---|---|---|
| 家宅 | 正妻1 · 侧室2 · 有孕1 | 名分、住处、身孕、子女 |
| 账目 | 现存644两 · 日入10.8两 | 产业、借贷、月支 |
| 朝堂 | 官职3 · 派系2 | 品级、派系势力、折子 |
| 军中 | 兵300 · 士气60 | 驻军、行军、战役、军饷 |

**晨报**：放看板最顶部一行，点开看全文。

## 3. 四条红线（破了必崩）

```
① 只有结算层能写 state（单一写者）
② 同一个 actionId 只结算一次（幂等）
③ 人不在场，不能当他在场说话
④ 死人的钱、妻、官，必须有人接手（继承）
```

**除此之外不设禁令**：杀人、纳妾、私盐、高利贷、挑唆、造反——都能干，只要承担后果。
