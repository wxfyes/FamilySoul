## 二、逐条说明

### ① 时间公理（这条比审查发现的更严重）

**审查只看到 `aging.js` 每 30 天长一岁；实际代码里还有第二套：**

```js
// clock.js:378（旧代码，一直在跑）
if (day % 360 === 0) a.age = (Number(a.age) || 20) + 1;
```

**两套并存 = 每年长 12 岁（我这套）+ 1 岁（旧代码）。**

**整改：**

```js
aging.js:  export const DAYS_PER_YEAR = 360;   // 与世界历法一致：四季各 90 日
clock.js:  删掉 day % 360 那行，长岁只由 aging.js 负责
秋收：      day % 30 → day % 360 === 240（一年一收，原先一年收 12 次）
```

**验证：**

```
第 1 日 → 春；第 91 日 → 夏；第 181 日 → 秋；第 271 日 → 冬
第 720 日（整两年）：相公 27 → 28（只长一岁）
第 400 日（非整年）：年龄不变
婴孩 0 岁 → 1 岁（原先被 age>0 判断挡掉，婴儿永不长大）
```

**一句实话**：一年 = 360 世界日，而世界是 1:1 与现实平行，
所以**现实一年，世界里才长一岁**。这正是"重活一世"该有的速度。
若你嫌慢，只改 `DAYS_PER_YEAR` 一个数（季节会跟着变，因为四季按年长的四分之一算）。

### ② 宗族乱认亲戚

**原代码：遍历所有宗族，只要相公名声好，陆氏/杨氏/周氏的族老全来登门。**

**整改：**

```js
本宗：    相公同姓那一族（王氏）
姻亲：    府内人 / 配偶是相公 / 相公的亲生子女 的姓氏（沈氏、林氏…）
商帮：    临江商帮
外姓宗族：关系不再随相公名声涨落，也绝不登相府的门
```

**顺手修了一个隐藏坑**：原来"亲眷"判定写的是 `a.relations?.husband`，
**而全城 NPC 都有 `relations.husband`**，等于全天下都算亲戚。
现在只认 household / spouse / 亲生子女。

**姓氏表**：从 12 个扩到《百家姓》全表（李、张、王、刘…都能成族）。

**验证：**

```
本地：王氏宗族、沈氏宗族、李氏宗族（李氏是外人）
连跑 10 次走动：只有王氏、沈氏来，李氏 0 次
线上负载：王氏宗族、沈氏宗族、林氏宗族、临江商帮（只这四家）
```

**另外**：全世界宗族 39 家，但只把与相公真有走动的那几家写进 App 负载，避免刷屏。

## 四、没做的 / 要提醒的

1. **一年 360 日 = 现实一年一岁**：这是物理自洽的代价。你若想快，改 `DAYS_PER_YEAR`（同时季节会自动跟着变）。
2. **月例、租金仍按 30 日一月**：与 360 日一年正好 12 个月，自洽。
3. **秋收改一年一次**后，粮仓增长变慢；如果觉得粮太紧，可把秋收量从 600 石调高。
4. **宗族目前只有"走动 + 闲话"**，还没有出资、举荐、联姻（上一轮报告已列为待做）。
