# 白皮书：App 双域改造 —— 虚拟世界 与 AI 助手 彻底解耦

> 版本：v1（待代码审查）
> 作者：天道引擎侧
> 状态：**设计稿，未动代码**
> 目标读者：接手写代码的人

---

## 0. 一句话目标

把现在的 App 拆成两个互不相干的东西：

```
① 虚拟世界（World）——现在这套：角色、NPC、时辰、产业、因果，全部照旧
② AI 助手（Assistant）——新的：纯问答，不读世界、不写世界、没有 NPC、没有记忆的"世界知识"
```

**两者共用一个 App、一个服务器进程，但代码路径、数据、提示词、成本核算全部独立。**

---

## 1. 最高原则（不可违逆）

| 编号 | 原则 | 违逆的后果 |
|---|---|---|
| P1 | 助手**不读**世界状态 | 助手会"看见"你的账本、私会、秘密 → 世界失去隐私 |
| P2 | 助手**不写**世界状态 | 一句话就能加银子、改位置 → 世界崩坏 |
| P3 | 助手**没有 NPC**、不推进剧情 | 否则等于第二个天道，两套剧情打架 |
| P4 | 世界**不因助手**改变任何数据 | 同上 |
| P5 | 隔离必须做在**路由/模块层**，不能只靠提示词 | 提示词可以被绕过 |

**判定方法（代码审查时看这条）**：`/api/assistant/*` 的实现文件里，**不允许 import 任何 `src/world/*` 模块**，也不允许读 `data/world/*`。发现即打回。

## 2. AI 助手规格（对标豆包）

### 2.1 能力

```
· 多轮对话，有上下文（每账号一份独立历史）
· 可以问任何问题：查资料、写东西、翻译、解释概念、出主意（与现实相关）
· 可以长回答、可以列点、可以拒绝不当请求
```

### 2.2 明确不做

```
✗ 不读世界账本（银子、人物、产业、线索、约定一概不知）
✗ 不改世界任何数据
✗ 不扮演世界里的任何角色（不写"【沈婉儿】：…"这种台词）
✗ 不与世界共享对话历史
```

### 2.3 存储

```
data/assistant/<memberKey>.json     ← 助手历史（独立）
data/world/state.json               ← 世界状态（助手永不触碰）
```

### 2.4 接口

```
POST /api/assistant/chat
body: { "text": "帮我写一份茶行开业请柬", "newSession": false }
resp: { "ok": true, "reply": "……", "usage": { "tokens": 312, "cost": 0.0009 } }

GET  /api/assistant/history?limit=30   → 本人历史（只读）
POST /api/assistant/clear              → 清空本人历史
```

### 2.5 成本核算

```
单独计数器：assistantUsage（按 member 累计）
世界另有一套 worldUsage
两者不得混算，看板分开显示
```

## 3. 注册与角色创建

### 3.1 注册表单字段（固定这几项）

| 字段 | 类型 | 规则 |
|---|---|---|
| 邀请码 | 文本 | **必填**，服务端校验（初期一条公用码即可，后期换一次性码） |
| 姓名 | 文本 | 2~4 个汉字；过命名规则；**世界内不得重名** |
| 性别 | 单选 | 男 / 女 |
| 年龄 | 数字 | 14 ~ 60 |
| 出身 | 固定值 | **普通百姓**（唯一选项；后续发展看天道） |
| 性情 | 多选 1~3 个 | 谨慎 / 贪财 / 嘴硬心软 / 心高气傲 / 老实本分 / 胆大 / 记仇 / 重情义（可扩展） |
| 来处 | 下拉 | **必须取自世界现有城池名**（如临江府、苏州府…），不允许自由输入 |

### 3.2 校验与提示（红字要求）

| 情况 | 行为 |
|---|---|
| 姓名已被使用 | **红字提示"此名已有人用"**，禁止提交 |
| 姓名不符合规则 | 红字提示"姓名须 2~4 个汉字，且不能是地名/疑问词" |
| 邀请码错误 | 红字提示"邀请码无效" |
| 年龄越界 | 红字提示"年龄须在 14~60 之间" |
| 来处不在列表 | 下拉里选不到，无法提交 |

**一个账号只能有一个角色**：已绑定的账号再进注册页 → 直接跳回世界，不允许再建。

### 3.3 角色初始化（进世界那一刻）

```
位置：该城池的【客栈】（不是别人家）
住处：一座普通民宅（小院，普通百姓规格），归他本人
盘缠：20 两（普通百姓起步，够活一阵，不够翻身）
产业：无
关系：对所有人 0 起点；NPC 对他"陌生"
标记：humanBound = true（真人角色，引擎不许摆布）
事件：写一条"外来人 X 入城"到事件流
天道：下一轮必须"认得这个人"（在建角色那一刻注入一条事实：新面孔与他的出身/性情）
```

### 3.4 之后的命运

```
娶亲 / 杀人 / 夺产 / 出家 / 经商 / 当官 —— 都可以
但全部由天道按世界阻力裁定，不许白拿
（引擎只提供代价与事实，不做判定）
```

## 4. 数据模型变更

### 4.1 账号（config.json 的 family，扩展字段）

```jsonc
{
  "family": {
    "u_abc123": {
      "token": "新发放的令牌",
      "actor": "npc_x",            // 绑定的角色 id
      "title": "张三",
      "kind": "player",            // 新增：player | staff
      "invite": "INV-2026-01",     // 新增：用掉的邀请码
      "createdAt": 1762...
    }
  }
}
```

### 4.2 角色（world.actors[actorId]，新增/复用字段）

```jsonc
{
  "id": "new_abc123",
  "name": "张三",
  "gender": "male",
  "age": 22,
  "role": "普通百姓",
  "origin": "苏州府",              // 来处
  "traits": { "谨慎": 60, "贪财": 55 },   // 性情（沿用现有 traits 结构）
  "home": "house_abc123",          // 分配的民宅
  "location": "inn_临江府",         // 进城的客栈
  "money": 20,
  "humanBound": true,
  "originKind": "player_created",
  "createdDay": 16
}
```

### 4.3 邀请码（world.flags 或独立文件）

```
data/invites.json → { "INV-2026-01": { used: false, usedBy: null, createdAt } }
```

### 4.4 助手历史（新目录）

```
data/assistant/<memberKey>.json → { messages: [{ role, text, at }] }
```

**打包更新包时**：`data/assistant` 属于易冲刷数据，**排除**（同 data/chat）。

## 5. 接口清单

### 5.1 注册

```
GET  /api/world/origins            → 可选来处列表（城池名，来自 world.places/cities）
GET  /api/world/invite/check?code= → { ok: true/false }
POST /api/register
body: { invite, name, gender, age, origin, traits: ["谨慎","贪财"] }
resp: 成功 → { ok: true, token, actorId, name }
      失败 → { ok: false, error: "此名已有人用", field: "name" }   ← 前端红字定位到字段
```

**注意**：注册成功即**自动登录**（写 token 到客户端），不需要再登一次。

### 5.2 助手（见 2.4）

### 5.3 世界（现有，不改）

```
/api/world/go|summon|confirm|todo|menu   ← 全部保留
```

## 6. 客户端改造

### 6.1 启动页（新）

```
┌─────────────────────────────┐
│        大道乾坤              │
│  ┌───────────┐ ┌───────────┐ │
│  │ 虚拟世界  │ │ AI 助手   │ │
│  │ 有角色有命 │ │ 纯问答    │ │
│  └───────────┘ └───────────┘ │
└─────────────────────────────┘
```

**两个门各自记住上次状态；顶部可一键切换，切换不丢对话。**

### 6.2 世界流

```
虚拟世界 → 已有 token 且已绑角色 → 直接进聊天
        → 有 token 未绑角色   → 注册页
        → 无 token           → 登录/注册页
```

### 6.3 注册页（新增）

```
姓名 [____]            ← 失焦即校验重名，红字提示
性别 (男)(女)
年龄 [__]
出身  普通百姓（固定显示，不可改）
性情 [谨慎][贪财][嘴硬心软]… 最多选 3
来处  [临江府 ▾]        ← 下拉，只能选世界现有城池
邀请码 [____]
              [ 入 世 ]
```

### 6.4 助手页（新增）

```
普通对话界面：输入框 + 气泡 + 清空 + 复制
不显示：位置条、同行、待办、抽屉、世界任何气息
```

### 6.5 设置分离

```
世界设置：服务器地址、角色令牌、语音
助手设置：模型、上下文长度、清空历史
两套互不影响
```

## 7. 安全与限流

```
① 邀请码必填（初期公用码，后期一次性码）
② 注册接口限流：同 IP 每分钟 ≤ 3 次
③ 姓名唯一性检查在服务端做（前端只做即时提示）
④ 助手接口按账号限频（每分钟 ≤ 20 次）
⑤ 助手历史只对本人开放（按 token 解析 member）
```

## 8. 分期计划与验收

### 一期（本次要做）

```
1. /api/assistant/chat + 历史 + 清空         验收：问"今天天气"能答；问"我有多少银子"答不出（因为不读世界）
2. 注册接口 + 邀请码 + 重名校验              验收：重名红字；年龄越界红字；进世界后有民宅 20 两
3. App 启动页两个门 + 注册页 + 助手页         验收：两个门都能进；切换不丢对话
4. 助手与世界历史彻底分开                     验收：查 data/ 目录，两份文件互不写入
```

### 二期

```
5. NPC 记忆按"与谁"分开（防止同一个人对两个真人说同一句话）
6. 多真人同场：相遇、同行、争产
```

### 三期

```
7. 私人位面（修仙/现代），realm 层已留好
```

## 9. 风险与回滚

| 风险 | 处理 |
|---|---|
| 注册接口被刷 | 邀请码 + IP 限流；可疑注册可一键封禁（账号 kind → banned） |
| 新角色破坏世界平衡 | 起点极低（20 两、无产业），全部收益靠天道判 |
| 助手"看见"世界 | 路由层隔离 + 代码审查（禁止 import world 模块） |
| 数据混乱 | 新增文件独立；注册失败不写任何世界状态（事务式：全部校验通过才落盘） |
| 成本失控 | 两套计数器分开；助手可用更便宜模型 |

**回滚方式**：注册功能由 `config.features.registration` 开关控制；关掉后启动页隐藏注册入口，已注册角色不受影响。
