# FamilySoul 产品化路线（2026-11-08）

> 定位：以「大模型即天道」为核心的古代人生叙事沙盒。
> 当前是**单机垂直切片**，不是多人在线产品。本文只谈上架/开放注册前必须补齐的硬门槛，
> 不谈愿景口号。

## 一、当前真实基线

| 项 | 现状 |
|---|---|
| 主服务 | `src/server.js`（单进程，3088） |
| 世界状态 | `data/world/state.json` 一份，约 4MB，`saveState` 全量写 |
| 鉴权 | 静态 token（`config.json` / 环境变量），无账号、无注册、无会话 |
| 用户 | 一个「相公」+ 一台客户端 |
| 对话 | 每轮约 1.2 万输入 token + 可选 TTS，成本按次计 |
| 架构 | `pet-service.js` 388 行，`src/chat/*` 分层，四套测试（21/4/20） |
| 部署 | 软路由 `/opt/familysoul`，热更新包 |

结论：**引擎和叙事层已经有底子；产品层（账号、租户、计费、合规）几乎为零。**

## 二、开放注册前的六道硬门槛

### 1. 租户隔离（最高优先级）
- 现在所有用户共享一份 `world/state.json`；
- 必须改成 `data/tenants/<tenantId>/world/`，每个账号一个世界；
- 世界引擎不感知租户：`dataDir` 已是注入参数，这是现成的切口；
- 共享世界（同一座临江城）是**第二阶段以后**的事，第一期不做。

### 2. 账号与鉴权
- 注册/登录/找回、密码哈希、会话 token、设备管理；
- 每个请求从「全局 token」改为「账号 → 租户」；
- 速率限制、防刷、封禁；
- 管理员后台与审计日志。

### 3. 成本护栏
- 按账号计量：LLM token、TTS 字数、生图次数；
- 免费额度 + 付费档位 + 硬上限；
- 超限降级（关闭 TTS/生图、缩短上下文），不能直接报错；
- 成本看板：单用户日成本、毛利。

### 4. 内容安全与合规
- 生成内容审核（输入/输出双向），敏感词与未成年人保护；
- 生成式 AI 服务备案、算法备案、实名认证（国内上架必需）；
- 隐私政策、用户协议、聊天记录留存与删除；
- 应用商店资质（软著、ICP/备案、隐私合规检测）。

### 5. 数据与运维
- 单文件全量写 → 需要事务/快照/按租户备份；
- 迁移脚本与版本号（`stateVersion` 已有，需可回滚）；
- 监控：进程、延迟、错误率、磁盘、LLM 失败率；
- 灰度发布与一键回滚（当前只有 stop/start）。

### 6. 客户端分发
- Android/iOS 签名、商店包、隐私清单；
- 强制更新与协议版本协商；
- 离线/弱网体验（当前强依赖服务端）。

## 三、三阶段路线

### 阶段 A：稳单机（现在）
- 保持四套测试全绿；
- 修完「活世界」的行为问题（行止、承诺、剿匪、招募）；
- 产出**租户抽象设计**，不急着写代码。

### 阶段 B：邀请内测（10~50 人）
- 账号 + 租户隔离 + 成本计量；
- 邀请码注册，管理员可封禁/重置；
- 每用户独立世界，互不干扰；
- 目标：验证留存、单用户成本、崩溃率。

### 阶段 C：开放注册
- 内容审核、实名、备案、支付；
- 自动扩缩容与多实例（世界状态按租户分片）；
- 客服与申诉流程；
- 共享世界/多人互动放到 C 之后单独评估。

## 四、现在就能做的三件事

1. **租户目录规范**：`data/tenants/<id>/`，先把 `dataDir` 全部走参数（已基本具备）；
2. **账号骨架**：`users.json` + 会话 token + 中间件，不接支付；
3. **成本计量**：每次 LLM/TTS 调用记 `tenantId, tokens, chars, ms`，先只记录不限额。

## 五、不做清单（防止跑偏）

- 不做共享大世界（直到单用户世界稳定且成本可控）；
- 不做实时多人同屏；
- 不做自研模型；
- 不在没有审核/备案前开放注册；
- 不为「像游戏」而牺牲「活人感」——行止由天道，潮汐由世界。
