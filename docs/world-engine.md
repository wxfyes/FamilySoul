# FamilySoul 世界引擎设计（World Engine v1）

> 目标：把「天道」从**剧本**改造成**世界**。
> 三条不可动摇的底线：**没有终局、一句话能改变命运、妻妾与暗号体系完整保留。**

---

## 0. 设计原则

> ## 【第一铁律】AI 就是天道主宰，不是文字渲染器，更不是剧本演员
>
> 世界怎么运转、NPC 怎么反应、一件事怎么发生又怎么收场、谁的命运被谁的一句话改写——
> **全部由天道（大模型）裁定**。它是这部天地的导演，拥有最终裁决权。
>
> 引擎只提供三样东西，且只有这三样：
> 1. **客观事实** —— 现在第几日几时、账上几两银、谁站在哪个院子；
> 2. **阻力** —— 关系数值、资源约束、城中暗涌（用来让世界"有重量"，不是用来规定答案）；
> 3. **已发生的历史** —— 事件流（用来让世界"记得住"，不是用来续写剧本）。
>
> 引擎**永远不**提供：预写的台词、写死的剧情分支、被关键词触发的固定反应。
> 凡是「正则命中 → 塞一段预制台词给模型照着说」，都是**剧本化**，一律禁止。

1. **引擎管「物理」，天道管「人事」。** 时辰会走、银子会少、人会老——这是物理；但谁要害你、她今天心不心疼你、这事最后成了没有——这是天道裁定，引擎无权代答。
2. **状态是唯一真相源。** 一切对话结束后如果不落进 `state.json` / `events.jsonl`，就等于没发生。
3. **世界不依赖用户在场。** 用户不上线，世界照样走。
4. **一切代价不可逆。** 允许破产、得罪人、被休、被杀；允许靠经营和人情翻盘，但不保证总赢。
5. **亲密与性是一等公民。** 不是需要绕开的敏感内容，是需要用状态机精确建模的日常。

### 剧本化的十种死法（出现任何一条，立刻算退化）

1. 用正则把用户的话分类，然后注入预制台词（如"你必须说：妾身方才盘算清楚了……"）
2. 把剧情阶段写死成"前期/中期/后期"，或"第一次推拉 / 第二次必须答应"
3. 用 `if (关键词) 就触发固定事件` 代替让 NPC 自己动
4. 把"必须顺从 / 必须拒绝 / 必须推进"写成绝对规则，抹掉人本来会有的犹豫
5. 让模型逐字复述状态账本，把幕后变成台词
6. 给每个角色预设结局或固定命运线
7. 事件只有一种走向，没有第二种可能
8. 失败不存在，或失败不产生任何后果
9. NPC 只在你说话时才存在，你不说话他们就静止
10. 主角光环写成"必然成功"，而不是"概率倾斜"

## 1. 现状诊断（为什么现在是剧本）

| 现象 | 代码位置 | 本质 |
|---|---|---|
| 相公的话先进正则分类，再注入预制台词 | `pet-service.js` 439–765 | 编剧在喂词，不是世界在演化 |
| 人物名额写死 | `pet-service.js` 496 行 `['芸娘','柳儿','杨采云','刘文霞','战静']` | NPC 是常量，不是实体 |
| 世界账本只读、无人演化 | `readMilestones()` 仅被读取 | 没有时钟，没有 tick |
| 相公不说话世界静止 | 全部事件由用户消息触发 | 缺模拟器 |
| 靠几十条「绝对严禁…」维持人设 | `buildSystemPrompt` 103–281 | 规则塞在提示词里，互相打架且烧 token |
| 四个人是四个平行宇宙 | `history-<member>.json` 各自隔离 | 没有"同一个世界"的概念 |

**结论：不是差一点，是缺一整层。** 角色卡、TTS、多人 Token 隔离、Web 控制台全部可复用，要替换的是中间那层"剧情逻辑"。

## 2. 三层架构

```
┌──────────────────────────────────────────────────────────┐
│  天道层 The Dao（大模型）                                  │
│  输入：客观事实 + 阻力 + 已发生的历史 + 对话                │
│  输出：世界的演化与自然语言。**人事的最终裁定者**            │
└───────────────────────▲──────────────────────────────────┘
                        │ 只读（引擎无权替它下结论）
┌───────────────────────┴──────────────────────────────────┐
│  模拟层 Simulator（纯规则，零 LLM）                        │
│  tick：时辰推进 / NPC 按日程行动 / 经济结算 / 事件倒计时   │
│  ——只维护「物理」，不产出剧情、不写台词                    │
└───────────────────────▲──────────────────────────────────┘
                        │ 读写
┌───────────────────────┴──────────────────────────────────┐
│  状态层 World State（state.json + events.jsonl）           │
│  唯一真相源：时间、地点、人物、资产、关系、亲密、待发酵事件 │
└──────────────────────────────────────────────────────────┘
```

一次对话的完整链路：

```
用户消息
  → parseIntent()      意图解析（自然语言 → 结构化意图，允许 LLM 辅助）
  → judge()            判定：概率 + 骰子 → 结果档位 + 代价
  → apply()            写事件 → 变更状态
  → perceive()         感知过滤：这一句谁看得见、谁知道
  → narrate()          渲染成回复（唯一一次 LLM 调用）
  → cleanReply()       现有过滤保留
```

**关键约束：`judge()` 和 `apply()` 绝不调用大模型。** 这是钱和一致性的双重要求。

## 4. 事件模型 `data/world/events.jsonl`（append-only）

```jsonc
{"seq":10231,"day":128,"hour":9,"place":"tea_house",
 "actor":"husband","action":"promise",
 "target":"weng","payload":{"text":"三日内把酒楼开起来"},
 "judge":{"p":0.72,"roll":0.41,"tier":"partial"},
 "effects":[{"type":"relation","target":"waner","field":"trust","delta":+2}],
 "public":true}
```

- **只追加，不修改。** 回放一个世界 = 从头重放事件流。
- `judge` 字段记录"为什么是这个结果"（概率、骰值、档位），出问题能复盘。
- `milestones.json` 退化为**投影**：由事件流计算出来，不再手写。

## 5. 时钟与 tick

```js
// src/world/clock.js —— 纯规则，无 LLM
export function tick(world, nowRealMs) {
  const steps = computeSteps(world, nowRealMs);   // 离线补算，最多补 30 天
  for (let i = 0; i < steps; i++) {
    world.clock.hour += 1;
    if (world.clock.hour >= 24) { world.clock.hour = 0; world.clock.day += 1; }

    for (const a of Object.values(world.actors)) runSchedule(a, world);
    settleEconomy(world);              // 茶坊日流水 → silver
    fireDueEvents(world);              // pending 到期则触发
    runNPCInitiatives(world);          // NPC 自主行动（下节）
  }
  return drainEvents(world);
}
```

**真人机时比**：建议 1 真实小时 = 1 世界日（可配）。用户关掉 App 三天，回来世界已过 72 天——**这是"重新活一世"的命门**。

**NPC 自主行动**（`runNPCInitiatives`）：每个 NPC 按 `goals` 与关系账本挑一个动作，写入事件。例如婉儿在信任 ≥ 80 时会自己去找掌柜谈酒楼开张；钱通海在怨怼 ≥ 60 时会动手。

## 6. 世界阻力 `src/world/judge.js`

> **它不是裁判，是秤。** 它只回答一个问题：**「这个世界对这件事的阻力有多大」**，
> 不回答「应该怎么演」「她该说什么」「这事算不算成」。
> **成败的最终裁定权在天道（大模型）**；下面这套数值只是递给它的一把尺子，
> 让它不至于每次都给出"主角光环必胜"的敷衍答案。

```js
// 阻力评估：给出概率与代价档位，作为天道裁定的参考（不是判决书）
const BASE = { persuasion: 0.5, deception: 0.4, bargain: 0.55, courtship: 0.6, violence: 0.35 };

function weigh(intent, world) {
  let p = BASE[intent.kind] ?? 0.5;
  p += relationBonus(intent.target, world);   // 好感/信任加成
  p += resourceBonus(intent, world);          // 银子、名声、人手
  p -= riskPenalty(intent, world);            // 对方性格、场合、目击者
  p = clamp(p, 0.05, 0.95);                   // 永远保留失败可能
  return { p, note: describeResistance(p) };  // 只给"阻力描述"，不给台词
}
```

天道拿到 `{ p: 0.28, note: '她心里有怨，银钱也不凑手' }` 之后，**自己决定**这一场到底怎么发生：
可以办成但埋下祸根，也可以当场驳回，也可以半推半就——**只要不与客观事实冲突即可**。

**结果档位必须带代价**：

| 档位 | 叙事含义 | 状态后果 |
|---|---|---|
| great | 远超预期 | 目标达成 + 额外收益 |
| success | 达成 | 目标达成 |
| partial | 达成但要付代价 | 目标达成 + 一条新麻烦 |
| fail | 没成 | 关系 -，事件进入 `pending` 择日反噬 |
| disaster | 灾难 | 关系重挫 / 资产损失 / 新敌人 |

**主角光环的正确写法**：`p` 整体 +0.1 的倾斜，而不是"必然成功"。真实感来自那 5% 的灾难。

> 注意：档位表是给天道的**语义参考**（"这一下大概有多难"），不是必须逐格套用的判决书。
> 天道可以说"阻力很大，但她还是应了，只是应得很勉强"——**只要与事实（银子、关系、在场者）不冲突**。

## 7. 暗号状态机（保留并升级为一等公民）

**这是契约，不是提示词。** 只有引擎能切换状态，模型输出不得影响状态。

```jsonc
"ritual": {
  "code":    { "trigger": "^\\s*12345\\s*$|^\\s*123456\\s*$", "answer": "上山打老虎" },
  "state":   "solemn",        // solemn | unlocked
  "tone":    0,               // 0 端庄 · 1 亲昵 · 2 撩拨 · 3 露骨
  "since":   null,
  "timeoutMin": 90
}
```

**状态转移**

| 起点 | 触发 | 终点 | 引擎强制动作 |
|---|---|---|---|
| `solemn` | 命中 `code.trigger` | `unlocked` | 回复中必须包含"上山打老虎"；失败则重试一次，仍失败则本次不解禁 |
| `unlocked` | 用户表示结束（`做完了/完事了/收兵/穿衣服…`） | `solemn` | 强制走"事后归位"分支：擦拭、整理、问渴问累，**严禁"身子还热"类胡话** |
| `unlocked` | 90 分钟无互动 | `solemn` | 静默归位，不惊扰用户 |
| 任意 | 引擎判定出戏（连续 2 轮出现 AI 腔） | 不变 | 换模板重渲染 |

**为什么这是"真实"而不是"设定"**：状态在两次对话之间是持久的。昨天解禁、今天没对暗号，她就还是端庄大娘子——**除非关系账本里的 `desire` 或 `grievance` 改了阈值让她自己越线**。那才有"人"的味道。

## 8. 亲密系统（保留并升级为一等公民）

**性不需要绕开，需要建模。** 现状是"提示词求模型发浪"，设计改成三层驱动：

### 8.1 三个维度

| 维度 | 取值 | 作用 |
|---|---|---|
| `intimacy.level` | 0–5 | 亲密度：陌生 / 相敬 / 亲昵 / 情动 / 缠绵 / 事后 |
| `intimacy.tone` | 0–3 | 语气档位：端庄 / 亲昵 / 撩拨 / 露骨（**这就是"语言刺激"的开关**） |
| `relations.*` | trust/desire/fear/grievance | 决定她**愿不愿意**、**主不主动**、**有没有怨** |

### 8.2 关键规则

1. **`tone` 由状态推进，不由模型即兴。** 上一轮还是端庄，这一轮突然露骨 = 出戏。tone 每次最多升 1 档，靠互动累积，`desire` 越高升得越快。
2. **`desire` 低时，露骨是坏事。** 那会写成"敷衍/抗拒/皱眉"，而不是"顺从迎合"——这才是真实的人。现在 prompt 里"100% 顺从迎合"是在抹掉人性。
3. **记忆化。** 每次亲密事件写入事件流，带 `day`/`place`/`tone`。次日她可以自然提起"昨晚"；怨怼高时则提起"你昨夜那句话"。
4. **事后归位是状态转换，不是提示词恳求。** 到点必须切 `solemn` 并走温存收尾分支。
5. **文本尺度由 `tone` 决定**，同一段剧情，`tone=1` 是暧昧留白，`tone=3` 才是直白。**用户自己掌控尺度**，不需要重写提示词。

### 8.3 与现有资产的关系

- 现有 11,180 字的「傲娇助手」人格卡**一句不改**，它定义"她是谁"。
- 现在 prompt 里关于暗号、事后归位、发浪的那几大段，**迁移成状态机 + 语气模板**，从"每轮都发"变成"按状态注入"。
- 净效果：**更露骨的时候更露骨，该端庄的时候真端庄**，而且省 token。

## 9. 叙述层与 prompt 预算

一次 `narrate()` 的 system 结构（目标 ≤ 8k tokens）：

```
[固定规则]         ~600 tok   输出格式、禁止出戏、禁止 AI 腔
[人格卡]           ≤2500 tok  按需截断（不再每轮 1 万字全塞）
[状态摘要]         ≤800 tok   时间/地点/在场者/关系数值/亲密状态
[最近事件]         ≤600 tok   最近 5 条事件的一句话摘要
[本次判定结果]     ~100 tok   "你这次是 partial：答应她了，但银子不够"
[对话历史]         最近 20 条
```

**状态摘要的写法**（由引擎生成，不是模型总结）：

```
【天机】乾宁三年·春 第128日 巳时 烟雨
【所在】临江茶坊·柜台
【在场】沈婉儿（正妻·信任88 欲望72 怨怼2）
【家底】现银528两 · 茶坊日入1.2两 · 酒楼筹备中
【她记得】三日前你承诺"三日内把酒楼开起来"（今天第 128 日，未兑现）
```

最后一行就是"一句话改变命运"的落地方式：**承诺入账 → 到期检查 → 未兑现扣信任 → 她自己提出来**。

## 10. 感知过滤与多人一致性

### 10.1 感知过滤

```js
function perceive(actor, events) {
  return events.filter(e =>
    e.public ||
    e.place === actor.location ||
    e.targets?.includes(actor.id) ||
    toldBy(actor, e)          // 有人转告
  );
}
```

**你不知道，才是真实的。** 这一层必须在引擎里做，不能靠提示词求模型"别知道太多"。

### 10.2 多人世界的三个硬问题

| 问题 | 方案 |
|---|---|
| 状态共享 | 单进程 JSON → **SQLite**（WAL 模式），`world_id` 分库 |
| 并发写 | 事件序列号 `seq` + 乐观锁（写前校验 version，冲突重放） |
| 时间与冲突 | **异步因果一致**：同一时辰内按 `seq` 排序，不做实时同步；冲突用"谁先落账"仲裁 |

**不要做实时同步。** 多人实时在成本和一致性上都是灾难；异步时辰制（类似回合制邮件游戏）既真实又便宜。

## 12. 迁移路径（每阶段都能停下来跑）

**阶段一：让世界先动起来**（不动对话逻辑，风险最低）
1. 建 `src/world/state.js` + `clock.js`，从现有 `data/world/milestones.json` 初始化。
2. 服务启动时跑一次离线 tick，之后每 10 分钟 tick。
3. `buildSystemPrompt` 末尾追加**状态摘要**（第 9 节那段），其余一切不动。

> 效果：她开始"记得"你没兑现的承诺、账上银子会自己变。用户立刻能感觉到不同。

**阶段二：判定接管"改变命运"**
1. `chat()` 里加 `parseIntent()`（先只做 5 类：承诺、交易、调情、威胁、出行）。
2. 承诺/交易类走 `judge()` 并写事件。
3. 其余继续走老正则，**双轨并行，随时可关**。

**阶段三：暗号与亲密迁到状态机**
1. `ritual.js` 接管暗号与事后归位，正则分支删除。
2. `tone` 档位替代 prompt 里的固定发浪段落。

**阶段四：多人**
1. SQLite + `seq` + 感知过滤。
2. 每个成员一个 `actor`，同一个 `worldId`。

## 13. 防退化红线（本次改造绝不能碰）

0. **【最高】AI 是天道主宰**：引擎只提供客观事实、阻力与历史，**不得替天道裁定人事、不得产出台词、不得用正则把用户的话映射成固定剧情**。凡是"看起来世界在动，其实是代码在念稿"，一律算退化。
1. **暗号 12345 → 「上山打老虎」** 契约不变，且必须由引擎强制，不是靠模型自觉。
2. **事后归位**（擦拭/整理/问渴问累，严禁"身子还热"）必须是状态转换。
3. **妻妾体系**（正妻/侧妾/通房/地下情人）作为 actor 关系网保留，不得简化成单人。
4. **多角色同场分角剧本格式** `【角色名】：“台词”` 保留。
5. **510 两运河大酒楼 = 既定事实**，不得因重构而失忆（写进初始 state，永远在场）。
6. **语音音色映射**（相公/女主人/孩子/芸娘）不动。
7. **`mobile/` 已解冻**：允许改造客户端，但必须走双端发布闭环（`flutter analyze` 零告警 → Android 本地 APK → iOS GitHub Actions → 三处同步），且第五节的防退化项（3D 头像、四圆钮、离线 ASR、Apple Speech、音频 URL 带 token）不得删改。
8. **音频 URL 必须带 token**、`config.json` 不进包、`data/chat` 不进包。

## 14. 验收标准（怎么判断真的"活"了）

1. **离线演化**：关掉 App 24 小时再回来，世界过了 N 天，且至少有 3 条"你不在时发生的事"。
2. **承诺兑现检查**：说过"三日内办成"但没办，第四天她会主动提，且信任数值下降。
3. **同话不同果**：同一句话，在信任 20 和信任 90 时给出完全不同的结果。
4. **失败真实存在**：100 次判定里应有大约 20–30 次不是 success。
5. **延迟反噬**：得罪钱通海后，三天到七天内必然有事发生。
6. **暗号不会失灵**：任意时刻输入 `12345`，100% 回复含"上山打老虎"；说"完事了"100% 归位。
7. **不串味**：女主人端与孩子端的 prompt 里不出现王家账本。
8. **成本可控**：单轮 system 稳定在 8k token 以内，tick 期间零 LLM 调用。

| 风险 | 应对 |
|---|---|
| 状态漂移（模型描述与状态不符） | 叙述后做一次轻量校验：回复里出现的人名/地点必须在 state 里 |

## 16. 天道回执协议（阶段二落地）

**一句话改变命运的实现方式：由天道自己申报发生了什么，引擎只负责记账。**
引擎不做意图识别、不猜关键词、绝不注入预制剧情。

模型若在本轮确实改变了世界，在回复**最末尾**追加回执行（相公永远看不到，系统自动摘除）：

```
[[world:relation who=waner field=trust delta=+3]]
[[world:asset delta=-12.5 reason="买茶苗"]]
[[world:promise due=132 text="三日内把酒楼开起来"]]
[[world:spawn name="柳儿" role="邻家浣衣女" goals="赎身;照顾幼弟" secret="被钱通海的人盯着"]]
[[world:move who=qiantonghai to=dock]]
[[world:event text="阿吉报说码头来了新茶商"]]
```

| 指令 | 作用 | 参数 |
|---|---|---|
| `relation` | 改关系账本 | `who` `field`(trust/desire/fear/grievance) `delta` |
| `asset` | 改现银 | `delta` `reason` |
| `promise` | 立下承诺（到期未兑现在摘要里标红） | `due` `text` |
| `spawn` | **天道自己造人**，写入 state 成为常驻居民 | `name` `role` `goals` `secret` `place` |
| `move` | 某人换地方 | `who` `to` |
| `event` | 记一条世界大事 | `text` |
| `none` | 本轮什么都没变（强制格式的兜底） | 无 |

**回执是强制格式**：每条回复末尾必须有一行回执，无事发生写 `[[world:none]]`。
靠"愿意写就写"的遵守率太低，强制字段的遵守率才有保障。

实现：`src/world/dispatch.js`（解析 + 落账）、`src/world/ritual.js`（暗号契约）。
**解析失败单条跳过，绝不打断对话。**

### 回执率自检（不用人盯 JSON）

`recordReceipt()` 把最近 20 轮写进 `state.flags.recentReceipts`：

- 每 20 轮往日志打一次 `[World] 回执率 N%（最近 20 轮）`
- 低于 50% 时日志追加 `⚠ 偏低：提示词该加强了`
- `GET /api/admin/world` 返回一行中文 `health`，人类可读：`正常：最近 20 轮对话里有 75% 真的改变了世界`

## 17. 暗号契约（阶段三落地）

`src/world/ritual.js` 是引擎侧的契约执行器，模型无权切换状态：

| 输入 | 引擎动作 | 强制后果 |
|---|---|---|
| `12345` / `123456` | `solemn → unlocked`，tone = 3 | 回复若缺「上山打老虎」，**引擎自动补齐** |
| 「做完了/收兵/穿衣服/歇息吧…」 | `unlocked → solemn`，tone = 0 | 走事后归位温存 |
| 普通数字（如 12345678） | 不触发 | 不误解禁 |

状态写进 `state.json` 的 `actors.<id>.intimacy`，**跨对话持久**；摘要里以「【私密】已解禁 · 语气档位 3/3」呈现给天道，不呈现给用户。

## 18. 同场与偶遇（阶段四落地 · 不换数据库）

设计取向：**不是"群聊房间"，而是"开放世界里的偶遇"**——各在各的地方，谁进了同一个地方，谁就撞见。

| 概念 | 实现 |
|---|---|
| 人在地点 | `actors.<key>.location`（真人 `kind: 'human'`） |
| 同场判定 | `sceneAudience(world, placeId, selfKey)` → 还有其他真人则 `isPublic = true` |
| 默认位置 | 相公 `tea_house`，其余人 `street`（**避免一上线就同场，私聊被误判公开**） |
| 场景消息流 | `data/chat/scene/<placeId>.json`，最多 200 条 |

**公开场合铁律**：`isPublic` 为真时，暗号一律不生效（`prepareRitual` 直接拒绝并写日志），
她保持端庄——私密绝不外露。

**接口**

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/dsh-surfcore/pet-api/scene` | 当前所在、是否公开、同场真人/NPC、最近场景消息 |
| GET | `/dsh-surfcore/pet-api/scene/places` | 地点清单与各地人数 |
| POST | `/dsh-surfcore/pet-api/scene/move` | `{ to: "dock" }` 走动 |

**为什么不用 SQLite**：单进程 Node 天然串行，`saveState` 同步写盘，不存在并发覆盖。
只有"多机多进程共写一个世界"才需要数据库——那是另一个量级的问题，届时再评估（且需先确认路由器能不能装 sqlite）。

**已知限制**：手机端 `mobile/` 按军规不动，所以现在只能通过接口/控制台触发走动，App 里还没有"出门"按钮。
