

## 三、第二层：婚配按世情推，废掉前端"无脑未婚"

```js
inferMaritalStatus(name, role, age, gender)
  寡/孀/亡夫/先夫 → widowed
  妾/二房/姨娘/通房/侍妾 → concubine
  ≥45 岁 → 按名字定：四成 widowed、六成 married
  ≥24 岁 → married
  <20 岁或丫鬟/姑娘 → single
```

**接入与前端：**

```
state.js 迁移：成年而无 marital 的人统一补（府内 → married）
server 负载：直接给 maritalText（中文），前端不再自己兜底
看板 maritalText()：优先用后端中文
```

**显示规则：**

```
widowed  → 寡居 · 操持营生
married  → 已婚（府内则"已婚 · 府内眷属"）
concubine→ 妾室
single   → 未婚 · 待字闺中
```

## 七、过程中发现的两个额外错误（已一并修掉）

1. **小翠的婚配矛盾**：她 `role = 贴身丫鬟`、`household = false`，
   但确有身孕——数据里没有任何字段能推出"她不是姑娘"。
   **处理**：加一条规则「有孕在身就不可能是待字闺中」，丫鬟类补成妾室。
2. **通房/侍妾被写成"已婚"**：名分应以身份为准，迁移与自愈都会强制纠正为妾室。

---

## 八、没做的 / 已知限制

1. **称谓表仍是规则表**（不是完整的古代称谓图谱），遇到"
   姨娘、乳母、接生婆、稳婆"这类边缘称谓，仍可能落到兜底区间；
   但已不再"只看职业"，落错时 heal 会按名字再纠一次。
2. **年龄是按名字长度定的稳定值**，不是随机：同一个人每次读档年纪不变。
3. **身子只覆盖到"绝经/幼女/有孕/经期/周期"五种**，没有病痛、产后虚弱等状态。
