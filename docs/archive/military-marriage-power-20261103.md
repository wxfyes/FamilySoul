# 权力与钱 —— 军法 · 联姻 · 党争 · 钱庄 · 牙行 · 盐 · 码头 · 粮（系统规格）

> 原则：**引擎只给阻力，不下禁令。**
> 能不能办成由天道判；办成之后的代价由账本给。
> 唯一必须守住的是三条一致性：**人在不在、账对不对、后果接不接得上。**

---

## 0. 动词与权限

| verb | 含义 | 谁有权 |
|---|---|---|
| `EXECUTE` | 军法处置（逃兵、叛将、违令、细作） | 只有 commander |
| `COURT` | 提亲、纳妾、娶妻、联姻 | 家主（husband）；家主不在时正妻可代办 |
| `ALLY` | 结盟、投靠、入伙 | 家主 |
| `MARCH` | 行军（已有） | commander |
| `SIEGE` | 攻城（已有） | commander |

**权限只判"够不够得着"，不判"该不该"。**

## 一、军法（EXECUTE）

### 1.1 对象与罪名

| 罪名 | 例 | 判定依据（账本） |
|---|---|---|
| 逃兵 | 行军中离队 | 行军期 location 不在队伍、士气低 |
| 违令 | 不听军令 | 前一轮 commander 下令后未执行 |
| 叛将 | 通敌 | 与敌方 bond 为正 / 收过对方银两 |
| 细作 | 刺探军情 | 被擒、有物证 |
| 劫掠扰民 | 攻城后失序 | 民心骤降、有苦主 |

### 1.2 处置方式（选择而非默认）

```
斩首示众 / 阵前斩将 / 杖责 / 削职 / 流放 / 赦免
```

**每一种都是参数，代价不同。**

### 1.3 数值影响（建议区间）

| 处置 | 军心 morale | 士气/畏威 | 逃兵率 | 民心 |
|---|---|---|---|---|
| 斩逃兵（公开） | **+5~10** | 畏 + | **-15%** | -2 |
| 斩名将（无实据） | **-15~25** | 愤 + | +10% | -5 |
| 杖责示众 | +3 | 怨 + | -5% | 0 |
| 赦免 | -8 | 恩 + | +8% | +3 |
| 连坐（斩全家） | +10 | 惧 ++ | -25% | **-15** |

**冤杀必须有独立后果**：`冤杀` 标记写入事件，后续哗变概率 ×3。

### 1.4 后果链

```
被斩者 → 亲族/旧部 怨气 +20~40（关系网红边）
       → 御史弹劾（若杀的是有官身者）
       → 军中夜变（军心 < 30 且冤杀 ≥1）
       → 敌国招降其旧部
```

### 1.5 状态字段

```js
world.executions.push({
  id, day, by: 'husband', target: actorId,
  charge: '逃兵', method: '斩首示众',
  evidence: 'public' | 'weak' | 'none',   // 有无实据
  witnesses: [actorId...],
  effects: { morale: +8, desertion: -0.15, minxin: -2 },
  wrongful: false
})
```

## 二、联姻 / 纳娶（COURT）

### 2.1 可娶性与代价（没有"不可娶"）

| 对象 | 门槛（阻力） | 她要什么 |
|---|---|---|
| 良家女 | 父母之命、聘礼 | 明媒正娶、名分 |
| 寡妇 | 族人、亡夫家 | 名节保全 |
| 青楼女子 | 赎身银、老鸨放人 | 脱籍、不被人轻贱 |
| 丫鬟 | 主家放人、她自己愿意 | 一个名分 |
| **官家女** | 家族政治判断、正妻位 | **正妻或平妻**，绝不为妾 |
| 有夫之妇 | 丈夫、律法、宗族 | **不是娶，是奸情线**（风险极高） |
| 出家人 | 寺观、官府 | 基本不可能，硬来是另一个故事 |

**"不可娶"从引擎里删除，改为"门槛极高 / 她不做妾"。**

### 2.2 名分阶梯（古代是一妻多妾）

```
正妻（1）      婉儿当前
平妻（0~1）    极特殊（救驾、联姻），需正妻点头
二房/侧室（多） 芸娘
通房（多）      小翠
外室（多）      不入府，名声风险最大
露水            不留名分
```

**娶官家女 → 她要求正妻或平妻**
→ 必须动婉儿：**降妻 / 平妻 / 休妻**，三选一，都是大事。

### 2.3 联姻带来的东西

```
势力 +（岳家派系）
关系网 +亲家边（bonds，score 40~60）
官场消息（每旬一条情报）
举荐（可补一个官缺）
嫁妆（银 100~800 两，视门第）
```

### 2.4 联姻的代价

```
站队（自动入某派系）
岳家索取：要官、要钱、要你办事（每 10~20 日一次）
御史注目（被弹劾概率 +）
正妻怨气 +20~40
家中分权（她带自己的人进府）
```

### 2.5 流程（五步，每步可失败）

```
① 往来  → 信任/欲望上升，旧事沉淀
② 提亲  → 聘礼/赎身银 + 她本人意愿
③ 家族  → 父母/族长/岳家点头（可被拒、可加价）
④ 名分  → 正妻态度（同意/冷脸/闹）
⑤ 入府  → 名分写入、住处、月例、关系网重算
```

### 2.6 状态字段

```js
world.marriages.push({
  id, day, wife: actorId, rank: '正妻|平妻|侧室|通房|外室',
  dowry: 300, faction: 'faction_li',
  demands: [{ type: 'office', due: day+30, done: false }],
  approvedBy: ['waner']
})
```

## 三、党争（ALLY + 派系）

### 3.1 派系生成

```
联姻 → 自动入岳家派系
结盟 → 可跨派系（风险：两边都不信）
```

### 3.2 派系状态

```js
world.factions = {
  faction_li: { name: '李党', leader: 'li_shangshu', power: 40, members: [...], stance: { 王甯: 'ally' } }
}
```

### 3.3 权力博弈（每旬推进）

```
本派系 power 上升 → 可举荐、可压弹劾
对方派系 power 上升 → 弹劾、查账、外放
```

**弹劾链（已有折子系统可接）：**

```
弹劾 → 查实/查无 → 罢官/留任 → 补缺 → 派系换血
```

### 3.4 反噬

```
站队 → 对方派系视你为敌（关系网红边）
两头下注 → 被识破 → 双方皆敌
岳家倒台 → 你被牵连
你倒台 → 岳家切割（婚约还在，人情没了）
```

## 五、管道落点（不新增分支）

```
Intent：EXECUTE / COURT / ALLY（动词扩展，参数化）
Gate  ：只判"够不够得着"
        - 人是否在手（被斩者在军中/在府）
        - 权限（是否 commander / 是否家主）
        - 钱（聘礼、赎身、嫁妆）
        - 名分位（正妻是否已占）
Apply ：写 executions / marriages / factions / bonds / treasury / memories
Narrate：天道写场面（不写"该不该"）
```

## 六、验收标准

```
① 斩逃兵 → 军心上升、逃兵率下降、被斩者亲族怨气上升（三条同时变）
② 冤杀名将 → 军心骤降、夜变概率上升、御史弹劾出现
③ 娶官家女 → 势力上升 + 正妻怨气上升 + 岳家开始索取
④ 弹劾链跑通：联姻 → 站队 → 弹劾 → 罢官 → 补缺
⑤ 同一 actionId 重放 → 不重复斩、不重复娶、不重复扣钱
⑥ 被斩者的产业按继承规则处理（不是凭空消失）
```

---

## 七、一条底线（不是道德，是一致性）

```
人不在场 → 不能当他在场被杀/被娶
账上没有 → 不能凭空多出聘礼或嫁妆
死了的人 → 不能再说话、再行动
```

**除此之外，世界不设禁令。**

# 第二部分 · 金融与商路

## 0. 货币与计价

```
1 两 = 10 钱 = 100 分 = 1000 文（铜钱）
银两成色：官银 95~99%，私银 80~95%（收银要验色，暗扣 1~3%）
```

**账本里只存一个数：`assets.silver`（两，两位小数）。**
其他都是**换算视角**，不新增字段。

---

## 一、钱庄（存、贷、汇）

### 1.1 三种业务

| 业务 | 说明 | 收益 | 风险 |
|---|---|---|---|
| **存银** | 存进去，按月给息 | 月息 0.3~0.8% | 钱庄倒了 → 本金没了 |
| **放贷** | 借出来，按月收息 | 月息 1~3%（急贷可到 5%） | 坏账、被赖、被官府查 |
| **会票** | 异地取银（凭票） | 汇水 1~2% | 假票、庄家跑路 |

**已有 `loans` 结构可直接复用**，补两条：`interestRate`、`issuer`（哪家钱庄）。

### 1.2 钱庄对象

```js
world.banks = {
  tongbao: {
    id, name: '通宝钱庄', city: '临江府', owner: 'qian_dongjia',
    reserve: 800,        // 库存现银
    deposits: 1200,      // 存户合计
    loans: [{ to, amount, rate, dueDay }],
    credit: 60,          // 信誉（0~100）
    status: 'open' | 'squeezed' | 'failed'
  }
}
```

### 1.3 三条硬机制（这才是金融好玩的地方）

**① 挤兑**

```
reserve < deposits × 30%  → 有风声就会挤兑
挤兑日 → 存户排队 → reserve 归零 → 倒闭
```

**② 倒闭与赔付**

```
倒闭 → 存户按 reserve/deposits 比例赔付
      → 你的存银可能只剩三成
      → 借了它钱的：债还在（换了债主）或一笔勾销（看谁接盘）
```

**③ 官借**

```
官府缺银 → 向钱庄"借"（实为摊派）
钱庄不肯 → 抄家 / 换个罪名
你替钱庄出头 → 你被盯上
```

### 1.4 你（玩家）能做的

```
存银吃息 / 借钱周转 / 开自己的钱庄 / 入股别人钱庄
做会票生意（跨城汇兑）/ 趁挤兑低价收庄 / 替官府办差
```

**开钱庄**：需本金 500 两 + 官府牌照（要打点）+ 账房先生 + 信誉 ≥ 40。

## 二、牙行（中介、抽佣、担保）

### 2.1 牙行做什么

```
说合买卖（房、地、货、人）
代收代付
担保赊账（买方欠账，牙行垫或作保）
抽佣：3~5%（大额可谈到 2%）
```

### 2.2 已有五家行会可升级

```
茶行 / 漕帮 / 屠行 / 绣行 / 牙行
```

**牙行是"万行之行"**——它不生产，它收过路钱。

### 2.3 机制

```js
world.brokers = {
  yahang: {
    id, name: '临江牙行', owner: 'ya_pozi',
    cut: 0.04,              // 佣金
    guarantee: 300,         // 可担保额度
    reputation: 55,
    deals: [{ day, item, amount, cut }]
  }
}
```

**三条玩法**：

```
① 走牙行做生意 → 安全但要抽成
② 绕开牙行私自交易 → 省钱但出事没人担（被骗、被抢、被告"私牙"）
③ 自己开牙行 → 收别人的过路钱（需行会点头，否则被打砸）
```

### 2.4 风险

```
牙行卷款跑路 / 担保的买方赖账 / 官府查"私牙"（无照经营）
同行砸店 / 行会把你的货压价
```

## 三、盐（专卖、盐引、私盐）

### 3.1 制度

```
盐 = 官督商销
盐引：官府发票，凭引支盐、凭引运销
无引贩盐 = 私盐 → 重罪（但暴利）
```

### 3.2 链条

```
灶户（煮盐） → 盐商（凭引收盐） → 运商（走水路） → 州县（批发） → 铺子（零售）
```

**每一环都有价差与盘剥：**

| 环节 | 价 | 抽成/成本 |
|---|---|---|
| 灶户出盐 | 1.2 两/引 | 官府压价、盐吏克扣 |
| 盐商收引 | 2.0 两/引 | 引价 + 打点 |
| 运商 | 3.2 两/引 | 水脚、损耗 3~8% |
| 州县批发 | 4.5 两/引 | 税 |
| 零售 | 6~8 两/引 | 铺面、伙计 |

### 3.3 私盐

```
私盐成本 1.5 两/引，卖 4.5 两/引 → 毛利翻倍
风险：盐捕查缉 / 盐商报复 / 官府抄没 / 同伙告密
```

**私盐是"高利润 + 高死亡"线，不是"禁止"线。**

### 3.4 盐引

```js
world.salt = {
  licenses: [{ id, holder: 'husband', quota: 50, city: '临江府', expiryDay }],
  price: 2.0,          // 每引
  privateSaltHeat: 20, // 私盐热度（0~100，越高查得越紧）
  officials: [{ name, greed: 70 }]  // 盐吏，打点成本
}
```

## 四、码头与漕运

### 4.1 码头是什么

```
货往来的咽喉：装卸、仓储、水脚、船帮、关卡
谁控码头，谁收过路钱
```

### 4.2 机制

```js
world.docks = {
  canal_dock: {
    id, name: '运河码头',
    owner: 'husband',        // 你已买下大酒楼，可延伸控码头
    throughput: 40,          // 日吞吐（船/担）
    fee: 0.02,               // 每担抽
    guards: 12,
    gangs: ['漕帮'],         // 把持的帮口
    risk: 15                 // 劫道/水匪
  }
}
```

### 4.3 玩法

```
① 收过路钱（稳定、得罪人）
② 自营货运（赚差价、要船、要人）
③ 漕粮（官差，利润薄但稳，出事要担责）
④ 水匪（劫别人的货，或剿匪拿赏）
```

### 4.4 风险

```
漕帮抬价 / 水匪劫船（损失 20~60%）/ 官府征用 / 货损 / 码头械斗
```

## 五、粮（米行、粮价、囤积）

### 5.1 价格由供需

```
丰年 → 粮价跌（0.8 两/石）
歉年 → 粮价涨（2.5 两/石）
灾年 → 暴涨（4 两+）→ 民变风险
```

### 5.2 玩法

```
囤粮 → 灾年抛售（暴利，但"囤积居奇"会被官府查、被百姓砸）
开仓放粮 → 民心大涨，钱少赚
粮仓 → 已有（court.grain），可私人建仓
```

### 5.3 与已有系统

```
grainPressure 上升 → 米价涨 → 民心降 → 民变链（已有）
```

## 七、风险系统（金融的骨架）

| 风险 | 触发 | 后果 |
|---|---|---|
| 挤兑 | 谣言 + 库存不足 | 钱庄倒、存银缩水 |
| 坏账 | 借方破产/跑路 | 本金损失 |
| 假银 | 收银不验 | 损失 5~20% |
| 私铸 | 市面铜钱掺假 | 物价乱、官府查 |
| 抄家 | 站错队/被弹劾 | 资产全没 |
| 官借 | 官府摊派 | 拿不回，或换官职 |
| 劫道 | 走货无镖 | 损失 30~60% |

## 十、验收标准

```
① 存银 100 两，一月后账上多出利息（金额可复核）
② 借 100 两，逾期未还 → 债主上门 / 抵押被收
③ 钱庄库存 < 存户 30% + 谣言 → 挤兑 → 倒闭 → 存户按比例赔付
④ 走牙行 vs 私自交易：前者抽成、后者有被骗风险（两条都真实）
⑤ 私盐被抓 → 抄没 + 官司；没被抓 → 利润翻倍
⑥ 码头被漕帮抬价 → 抽成下降或械斗
⑦ 囤粮到灾年抛售 → 暴利 + 官府查办概率上升
⑧ 同一 actionId 重放 → 不重复扣钱、不重复放贷
```

## 十一、底线（一致性，不是道德）

```
钱必须从某处来、到某处去（守恒）
借了必须有人还（不能凭空勾销）
人在不在、货在不在，决定能不能做
```

**除此之外，金融系统不设禁令——私盐、高利贷、囤积、挤兑做空，都可以干。**

# 第三部分 · 上线纪律（不许抢戏）

> 这一部分不是功能，是**约束**。违反它，前面所有系统都会被玩家骂成"查账机器人"。

## 一、三条隔离规则

### ① 静默运行

```
钱庄挤兑 / 盐价涨 / 码头械斗 / 粮价波动 / 党争推进
→ 全部在世界 tick 里算
→ 不进对话、不弹窗、不打断、不主动播报
```

**世界照常运转，玩家不问，就不说。**

### ② 只在相关时露一句

```
触发条件 = 话题命中 且 在场者相关
```

| 玩家在聊 | 可注入 | 不可注入 |
|---|---|---|
| "这银子哪来的" | 钱庄、铺子进项 | 盐引、党争 |
| 跟盐商谈买卖 | 盐引价、私盐风险 | 粮价、码头抽成 |
| 跟她调情 | **什么都不注入** | 任何账目 |
| 跟官场人吃饭 | 派系、弹劾风险 | 铺子流水 |
| 行军 / 攻城 | 军饷、粮草 | 钱庄存银 |

### ③ 默认沉默，最多三条

```
每轮注入的事实 ≤ 3 条
没有触发词 → 0 条
宁可少说，不可多说
```

## 二、四条"不许"

```
❌ 不许 NPC 主动报账（"妾身瞧过账本，今日进项……"）
❌ 不许把数值念出来（"你的信任度是 62"）
❌ 不许在亲密/争吵/劝和场景里提钱
❌ 不许用账本事实盖掉她的情绪（她想吃醋就吃醋，别用"账上没这笔"堵回去）
```

## 三、账号隔离（双真人）

```
紫嫣的账号里，不许出现"王家的账"细节
她的账号只看到：她自己的铺子、她自己的人、她自己听到的传闻
```

**同一个世界，不同的人知道的不一样。** 这是真实感的核心。

## 四、成本与延迟

```
金融/军法/党争 全部本地计算，不增加任何 LLM 调用
注入只在拼提示词时做字符串筛选
```

**不许因为这些系统，让每轮对话多一次模型调用。**

## 五、验收（量化）

```
① 跟她闲聊 10 轮：她主动提钱/账/盐/官场 ≤ 1 次
② 调情场景：账本注入 0 条
③ 问"银子哪来的"：能答，且只提 1~2 条相关
④ 双端：她的账号看不到王家细账
⑤ 延迟：注入前后，单轮耗时差 < 100ms
```

**第 ① 条不过，就是抢戏，必须收紧。**

## 六、一句话

```
账在后台走，情在台前演。
世界可以很复杂，但她开口时，只说她此刻该说的话。
```

# 第四部分 · 待建骨架（路线图）

> 这些不是新玩法，是**让世界自洽的骨头**。按优先级排，P0 不做会反复出事。

## P0 · 结构件（先保命）

### ① 事务与补偿

```
一次动作横跨多个系统（钱 / 名分 / 关系网 / 派系 / 住处）
必须：全成，或全退
```

**现状风险**：钱扣了、人没进门；地造了、人没过去。

**验收**：一次失败的动作，事后对账，任何一处都不能只改一半。

### ② 世界日志可查（晨报）

```
你不在的六个时辰里发生了什么 → 一份"晨报"
粮价、械斗、谁家办丧事、谁被弹劾、谁在说你坏话
```

**这是"世界活着"最直接的证据。**
`events.jsonl` 已经在写，缺的是**聚合与呈现**。

### ③ 快照与回滚

```
每日一份 world 快照
一键回到某天（误操作 / 改坏数据 / 想重来）
```

**验收**：能回到任意一个快照点，且之后的事件不串。

### ④ 调参面板

```
粮价基准·税率·利率·军饷·民心衰减·生育率·病亡率
全部可调，不写死在代码里
```

**验收**：改一个数，世界表现随之变化，不用重新打包。

# 第五部分 · 补齐细节（实现前必读）

> 前四部分是"有什么"，这一部分是"边界在哪、怎么对账、怎么验收"。
> 缺了这些，系统能跑，但会漂。

## 一、名分冲突矩阵（多妻制的秩序）

一妻多妾，必须能排出**位次**，否则家里会乱。

| 位次 | 名分 | 人数 | 子女身份 | 继承顺位 |
|---|---|---|---|---|
| 1 | 正妻 | 1 | 嫡子 | 第一 |
| 2 | 平妻 | 0~1 | 视同嫡（需家主明示） | 第二 |
| 3 | 侧室/二房 | 多 | 庶子 | 第三（按母位次） |
| 4 | 通房 | 多 | 庶子（低） | 第四 |
| 5 | 外室 | 多 | 不入族谱 | 无 |

**冲突规则：**

```
① 正妻在，不得立平妻（除非正妻点头或休妻）
② 平妻需正妻书面/口头认可，否则家中怨气 +20
③ 位次决定：月例、住处、子女排序、宴会座次
④ 位次不是永久的：失宠/无子/犯错 → 可降
```

**子女排序（继承用）：**

```
嫡长子 → 嫡次子 → 平妻子 → 侧室子（按母位次）→ 通房子 → 无子则过继
```

## 二、婚姻的退出机制（不能只有"娶"）

```
和离    双方同意，写一纸离书，嫁妆退还（可谈）
休妻    七出（无子/淫/不事舅姑/口舌/盗窃/妒/恶疾）
        但"三不去"限制：有所娶无所归、与更三年丧、前贫贱后富贵
丧偶    一方死亡 → 守孝（27 个月）→ 可再嫁/再娶（有争议，看门第）
改嫁    寡妇改嫁需族人点头；带走嫁妆与否是官司
```

**每种都要有：关系网变化、旧事记录、子女归属、财产分割。**

## 三、军法的适用边界（军中 vs 民间）

```
军中：逃兵、违令、叛将、细作 → 军法处置（EXECUTE）
民间：杀人、盗窃、通奸、赖账 → 县衙审（已有 cases）
交叉：军士在民间犯案 → 先由军中拿人，还是县衙拿人？→ 看"军籍"
```

**规则建议：**

```
有军籍者 → 军中优先，县衙只能行文索人
无军籍者 → 县衙优先
军法杀人 → 需报备（否则被弹劾"擅杀"）
```

## 四、EXECUTE 与战役的交互

```
① 一次战役每回合只能执行一次 EXECUTE（与 MARCH/SIEGE 共用行动）
② 执行顺序：EXECUTE 先结算士气，再结算本回合战斗
③ 阵前斩将：本回合攻城加成 +10%，但被斩者旧部不发力
④ 战后清算：可秋后算账（延后执行），不占战役行动
```

## 五、派系影响任免的算法（不要凭感觉）

```
举荐权重 = 派系 power × 0.6 + 你的官声 × 0.3 + 贿赂 × 0.1
弹劾成功率 = 对方 power / (对方 power + 你的靠山 power) × 证据强度
补缺概率 = 你在候补池的排位（派系优先）
```

**证据强度：**

```
物证/人证 = 1.0
风闻        = 0.4
无凭        = 0.1（但仍可能"莫须有"，概率另算）
```

## 六、金融对账（守恒公式）

**每日结算必须满足：**

```
期初 silver + 当日收入 - 当日支出 = 期末 silver
```

**收入口径：** 铺子日入、俸禄、税、盐课、利息
**支出口径：** 工钱、军饷、房钱、聘礼、税、利息支出、赈灾

**跨系统核对：**

```
资产表（properties 日入合计） → 必须出现在 treasury 收入里
loans 余额合计 → 必须等于"应收"
banks.reserve + 在外放贷 → 必须等于 deposits（近似）
```

**任何一项对不上 → 打 `[Audit]` 警告，不进玩家视野。**

## 七、事件条目 schema（统一，便于晨报/快照/回放）

```js
{
  id: 'evt_...',
  day, hour,
  type: 'battle' | 'execution' | 'marriage' | 'finance' | 'disaster' | 'court' | 'birth' | 'death',
  actor, target, place,
  payload: { ... },        // 各系统自定义
  isPublic: true | false,  // 能否进晨报/传闻
  witnesses: [actorId],    // 谁看见
  effects: { silver, morale, minxin, grievance, ... }
}
```

**晨报 = 过滤 isPublic && witnesses 包含玩家或其耳目 的事件。**

## 八、失败与反噬模板（每个系统三件套）

| 系统 | 失败形态 | 可见后果 | 恢复路径 |
|---|---|---|---|
| 军法 | 冤杀 | 军心崩、夜变 | 抚恤、平反、斩监军 |
| 联姻 | 被拒/被讹 | 名声损、钱没了 | 换门第、托人说合 |
| 党争 | 站错队 | 罢官、抄家 | 投靠胜方、外放避祸 |
| 钱庄 | 挤兑 | 存银缩水 | 变卖资产、官借 |
| 盐 | 被查 | 抄没、官司 | 打点、顶罪、跑路 |
| 码头 | 械斗 | 抽成断、人伤 | 请镖、结盟、让利 |
| 粮 | 囤积被查 | 罚没、民怨 | 放粮、赈灾、减价 |

**每个系统都必须能"失败"，而且失败后世界还在。**

## 九、天道与引擎的分工（防剧本/防查账）

| 只能引擎做 | 只能天道做 |
|---|---|
| 位置、在场、钱数、兵力、日期 | 说什么话、什么表情、什么气氛 |
| 谁跟谁走、谁被斩、谁嫁进来 | 她愿不愿意、她怎么推脱、她怎么心动 |
| 数值结算与日志 | 场面描写与人物反应 |
| 拒绝的**事实**（不在场/没钱） | 拒绝的**说法**（娇羞/冷脸/哭闹） |

**引擎给事实，天道给表演。越界即退化。**

# 第六部分 · 客户端与信息分层（防晕）

> 系统越复杂，越不能把复杂度倒给玩家。
> 原则：**文字负责"演"，面板负责"看数"。**

## 一、三层结构

```
① 聊天层   全文字：叙事、情绪、决定
② 短语层   打字，或 1~3 个 chip：高频动作
③ 面板层   数字、清单、地图、关系：看板 / App「世界」页
```

**把"账本、清单、选项"塞进对话，就是晕的根源。**

## 二、每个系统在哪出现

| 系统 | 对话里（只出结论与决定） | 面板里（细节） |
|---|---|---|
| 军法 | "斩了。""谁求情？" | 军中名册、士气、逃兵数 |
| 联姻 | "她家要什么？" | 名分位次、聘礼清单、岳家诉求 |
| 党争 | "谁在参我？" | 派系势力图、弹劾列表 |
| 钱庄 | "挤兑了？" | 存款 / 放贷 / 库存三行数 |
| 盐 | "这批引子多少钱？" | 引票、配额、私盐热度 |
| 码头 | "今晚谁守？" | 吞吐、抽成、把持帮口 |
| 粮 | "仓里还有多少？" | 存粮、粮价曲线、民变阈值 |

**规则：对话只出"一句结论 + 一个决定"，细节去面板。**

## 三、防晕四条硬规则

### ① 一次只抛一个决定

```
❌ 同时弹：纳妾？借钱？打谁？
✅ 当前这件事，只有 A / B / 不做
```

### ② 决策卡折叠细节

```
卡面：一句话现状 + 代价 + 两个选项
点「详情」才展开数字
```

### ③ 通知分三级

```
打断：城破、人死、被弹劾、她跑了
晨报：月结、婚约、粮价、派系变动
静默：日常流水，只进账本
```

### ④ 长状况能压成三行

```
一个按钮："现在什么情况？"
→ 三行话，不带数字
```

## 四、客户端怎么改（改动很小）

```
聊     ← 基本不动
世界   ← 把看板内容搬进 App：城志 / 人物 / 关系 / 军中 / 账目
我     ← 家宅、名分、银两、产业
```

**现在是「聊 + 我的世界」两个页面，够用。不必做成 SLG。**

**中期建议的「世界」页四块卡片：**

```
军中：兵、粮、士气、在打哪
家宅：名分位次、各房开销、子女
账目：银两、日入日支、借贷、产业
朝堂：官职、派系、折子、敌友
```

## 五、全文字能不能玩

```
✅ 日常、感情、权谋对话 —— 文字最好
❌ 军力对比、账目核对、名分排序 —— 文字反人类
```

**结论：可以全程不打字，但不能全程不看面板。**

## 六、实施节奏

```
短期：聊天里只加"一句结论 + 一个决定"
中期：App「世界」页按 军中 / 家宅 / 账目 / 朝堂 做四块卡片
长期：地图 + 关系网可视化
```

## 七、一条禁令

```
❌ 不做常驻菜单
❌ 不做"选择你的回答"
❌ 不做每句话挂按钮
```

**那是手游，不是这个世界。**

# 第七部分 · 实施路线（分步、可验收）

> 结论先说：**不要一次性搞完。**
> 一次只做一条腿，做完验收、跑回归、再下一条。
> 之前"改一处坏一处"，就是因为并行改三条腿。

## 零、总原则

```
① 先保命，再加玩法：降本 → 可观测 → 防丢钱，然后才谈新系统
② 一条腿做完再下一条：新系统必须"有 / 能离线跑 / 可观测 / 有代价"四格全绿
③ 每步都有回滚点：改前打快照
④ 每步都有验收：脚本能跑，人眼能看
```

**目标：让它跑得起、看得见、敢动。**
