# 第二人生沙盒四支柱 · 架构审查与深层缺陷纠偏报告

> **审查定位**：独立架构师深度审阅  
> **审查对象**：`docs/report-sandbox-four-pillars.md` 及实际代码提交 `0890e3f`（7 个关联文件）  
> **核心军规**：不打补丁，有病治根（修架构、修单一入口、修规则闭环）  
> **审查结论**：骨架方向非常敏锐，四根支柱（物候、物价、岁时、宗族）全部落地；但代码中存在**两处严重违背物理常识的时空与人伦硬伤，以及三处数据架构未闭环缺陷**，必须立即纠偏，否则世界逻辑会严重失真！

---

## 一、 整体肯定：令人赞赏的扎实之处

1. **物价宏观指数化**：采用 `base`（基准）+ `index`（全国指数）+ `cityFactor`（城景气），既保留了经济波动弹性，又不需要给几万个物品记死流水账，架构非常优雅。
2. **运河冰封与行军阻断**：冬天水运停摆、雨雪行军翻倍，天时开始真正物理阻断人谋，彻底脱离了“天气只是文案描写”的假沙盒。
3. **道统制约称制野心**：将名声（fame）与大义名分（legitimacy）硬挂钩，名分不足直接在物理层驳回称制，让儒家礼法有了真实戒尺。

## 二、 核心硬伤与致命逻辑缺陷（必须治本）

### 🔴 硬伤一：时间尺度严重撕裂（春天还没过完，人已经老了 3 岁）

- **事实代码定位**：
  - `src/world/state.js:44`（季节定义）：
    ```javascript
    export function seasonOf(day) {
      const idx = Math.floor(((Math.max(1, day) - 1) % 360) / 90);
      return SEASONS[idx] || 'spring';
    }
    ```
    世界的季节系统明确定义：**360 个世界日 = 1 年**（春夏秋冬各 90 天）。
  - `src/world/aging.js:16`（长岁定义）：
    ```javascript
    export const DAYS_PER_YEAR = 30; // 每 30 天长一岁！
    ```

- **荒唐后果**：
  - 春季 90 天，刚到季末，角色已经在岁数上**长了 3 岁**！
  - 现实中过完一次春夏秋冬（1 真实世界年，360天），世界里的所有人居然**老了 12 岁**！
  - 相公原本 27 岁，世界时间只走了 3 年，相公就变成了 63 岁体魄衰朽的垂暮老翁；
  - 刚出生的婴儿在春天的三个月里瞬间变成了 4 岁幼童，天时节气与肉身岁月彻底撕裂！

- **根治方案**：
  **世界的日历尺度必须统一。**
  若世界以 360 天为一公转周期（春夏秋冬各 90 天），岁时长岁必须以 360 天为一岁基准；若为了体验节奏希望长岁更快，必须连同季节周期（如改 120 天为一年、每季 30 天）**同步调整**，绝不允许“一季过完人长三岁”的物理悖论。

### 🔴 硬伤二：宗族血缘断层（全天下所有异姓宗族，全向王家相公登门）

- **事实代码定位**：
  - `src/world/clans.js:70-84`：
    ```javascript
    const me = world.actors?.husband;
    const fame = num(me?.fame?.value);
    for (const clan of Object.values(world.clans)) {
      // 遍历所有宗族（沈氏、林氏、王氏、陆氏、杨氏、周氏、吴氏...）
      const drift = fame >= 30 ? 3 : fame <= -30 ? -4 : 1;
      clan.relation = Math.max(0, Math.min(100, num(clan.relation) + drift));
      if (clan.relation >= 60 && Math.random() < 0.5) {
        events.push(nextEvent(world, {
          payload: { text: `${clan.name}的族老登门走动，话里话外想求你提携族中后辈` }
        }));
      }
    }
    ```

- **荒唐后果**：
  相公姓**王**，正妻沈婉儿姓**沈**，二房林芸娘姓**林**。
  代码跑起来后，因为相公名声好，**陆氏、杨氏、周氏、吴氏、赵氏的族老居然也全往王家大宅跑，登相公的门求提携族中后辈！**
  中国传统宗法社会讲究“非我族类，其心必异”，外姓族老不可能向一个异姓陌生人登门认亲求恩荫。

- **根治方案**：
  宗族登门走动必须**严格校验血亲与姻亲纽带**：
  - **本宗族老**（王氏宗族）：以族中长辈或提携晚辈身份走动；
  - **姻亲宗族**（沈氏宗族、林氏宗族）：以岳丈家、姑爷回门或娘舅走动身份登门；
  - **商帮组织**（临江商帮）：以会馆同侪、行首请客身份拜访；
  - **其余异姓宗族**：走动只发生在其各自族内，绝不可全跑来拜访相公。

### 🟠 缺陷三：物候收益率双重叠加暴击（春茶秋酒被重复加权）

- **事实代码定位**：
  在 `src/world/clock.js:1536-1537` 中，计算产业日入时已包含：
  ```javascript
  if (/茶/.test(String(prop.name || ''))) rate *= season === 'spring' ? 1.3 : season === 'winter' ? 0.85 : 1.05;
  if (/酒/.test(String(prop.name || ''))) rate *= season === 'winter' ? 1.35 : 1.1;
  ```
  而在紧接着的 `clock.js:1554` 又执行了一遍：
  ```javascript
  rate *= propertySeasonFactor(world, prop); // 内部对春茶又 ×1.15，冬酒又 ×1.2
  ```

- **后果**：
  春茶复合收益率高达 `1.3 × 1.15 = 1.495`（暴涨 50%）；冬酒复合 `1.35 × 1.2 = 1.62`；冬茶则惨遭两次斩杀跌至 `0.72`。老逻辑与新模块双重叠乘，造成了严重的数值通胀与异常震荡。
- **根治方案**：
  彻底废除 `clock.js` 内部旧有的个案正则特判，收益率计算**单一收口至 `propertySeasonFactor`**。

### 🟠 缺陷四：灾后疫病一刀切（一城受灾，全国 56 城同时感染）

- **事实代码定位**：
  `src/world/season.js:67-71`：
  ```javascript
  for (const ct of Object.values(world.cities || {})) {
    if (!ct) continue;
    ct.unrest = Math.min(100, num(ct.unrest) + 5);
  }
  ```
- **后果**：
  哪怕只是偏远的泉州府遭了旱灾，疫病判定一旦触发，幽州府、大同府、成都府、长安府**全国 56 座城全境瞬间民心同时 +5**。
- **根治方案**：
  疫病应当发生在**受灾城池及其相邻府县（查 `geography.js` 的邻接道）**，局部蔓延扩散，而不是全国神仙感染。

---

### 🟡 隐患五：名分硬编码与宗族白名单个案穷举

1. **名分函数硬编码**：`src/world/reputation.js:53`：
   `const cities = (world.factions?.wangjia?.cities || []).length;`
   计算任何 `actorId` 的名分时，居然全都写死读“王家”的城池数；其他诸侯领袖算名分时被强行绑在王家地盘上。
2. **姓氏白名单穷举**：`src/world/clans.js:16`：
   写死了 12 个姓氏（`['沈', '林', '王', '陆', '杨', '周', '吴', '陈', '刘', '赵', '钱', '孙']`），导致天下第一大姓“李”与第二大姓“张”哪怕有 10 位官员名士，也永远无法成立宗族。

## 三、 整改清单与建议落地策略

| 序号 | 缺陷项 | 严重级别 | 根治措施 |
|---|---|---|---|
| 1 | **时间尺度撕裂** | 🔴 物理死锁 | 岁时 `DAYS_PER_YEAR` 与世界年基准统一对齐，告别“一季老三岁” |
| 2 | **宗族乱认亲戚** | 🔴 人伦混乱 | 宗族走动严格区分【本宗血亲】、【妻妾姻亲】与【外部商帮】 |
