## 一、这次改了什么（按层分）

### 1. 税率语义修正（数据结构层）

**问题**：`Number(ct.tax) || 10` 把「税率 0（免税）」当成「没填（默认 10%）」，免税城在暗中交税。

**改动**（`src/world/clock.js`）：

```js
// 之前
const tax = Math.max(0, Math.min(50, Number(ct.tax) || 10));
// 之后
const rawTax = Number(ct.tax);
const tax = Math.max(0, Math.min(50, Number.isFinite(rawTax) ? rawTax : 10));
```

同样修正了另外三处：
- `raise_tax`（加税）
- `lower_tax`（减税）
- 国库告罄时的「全城加税 +2」

**一次性数据矫正**（`src/world/state.js`，`flags.taxBackfillDone` 守卫）：

```
[Tax] 一次性矫正 56 座城的税率 → 10%（此前被 || 10 暗中征收）
```

**此后 0 就是真免税**，天道下「免赋三年」的旨会真的生效。

### 2. 国库改为国家尺度（尺度层）

**问题**：国库 420 两，玩家一座宅 450 两——朝廷比一户人家还穷。

**改动**（`src/world/clock.js` 的 `runTreasury`）：

```js
const K = 100;                       // 民间 1 两 = 国库 100 两
const grossIncome = income * K;
const salaryPay  = expense * K;
```

**初值与阈值**：

```
国库初值     1200      → 1,200,000 两
欠俸阈值      300      →   300,000 两
```

**一次性迁移**（`flags.treasuryScaleDone`）：存量低于 10 万的存档直接抬到 120 万；昨日收支（`lastIncome/lastExpense`）也一并换算成国库尺度（`flags.treasuryLastScaled`，补做一次）。

**线上实测**：

```
[Treasury] 国库改按国家尺度记账：1200000 两（原 420.71 两）
```

### 4. 制度性损耗与贪墨（制度层）

**设计意图**：国库不是「收得少」才空，是「路上被吃掉」才空。

```js
// 损耗率：6% 起步，朝廷压力越高漏得越狠，封顶 35%
const skimRate = Math.min(0.35,
  0.06
  + courtPressure / 400
  + (courtBankrupt ? 0.05 : 0));
const skim = grossIncome * skimRate;
```

**贪墨入私囊**（30% 的损耗按官数均分给在任官）：

```js
const each = (skim * 0.3 / holders.length);
holderActor.money += each;          // 官员私银每天涨
```

**意义**：官手里有闲钱、有动机、有门路——**这是「官商勾结」得以发生的物质条件**。引擎只提供这个事实，不安排任何结果。

### 5. 赈灾支出与「拨不出」（状态机层）

```js
const relief = disasters * 5000;    // 每次灾荒拨 5,000 国库两
// 够钱：出账、民心 -2
// 不够：国库归零、朝廷压力 +5、全城民心 +4、
//       发事件 relief_short「国库拨不出赈灾粮款，灾民聚于城外」
```

**这条链是这次改造的核心**：灾荒 → 赈灾 → 拨不出 → 民怨 → 加税 → 税基缩 → 更穷。全程没有一句台词、没有一个「王朝将亡」的标记。

### 7.（同日）产业收入模型改造（经济规则层）

**问题**：投入 510 两的酒楼，日入固定 10 两，51 天回本，不像做生意。

**改动**（`src/world/clock.js` 的 `dailyIncomeOf`）：

```
日进项 = 产业本金(capital) × 日收益率
收益率基准 2.5%，乘：景气 / 民心 / 季节 / 掌柜信任 / 人手(每人+30%，封顶2.5x) / 商誉(开店天数)
单日收益率封顶 12%
利润的 25% 滚回本金（再投资），生意越长越大
```

**只有「正常营业 / 已开张」进项**；`自住府邸 / 筹备中 / 歇业` 归零（这条是本地步进测试时抓到的 bug：王宅曾被算成 19.44 两/日）。

**补偿的写法**：测试期前就开着的产业，`openedDay = 1`（视同第 1 日开张）**落成数据**，同时删掉了原来的 `daysOpen = Math.max(3, curDay)` 兜底——补偿从此能在账上查到，不再藏在公式里。

## 三、需要你审阅/拍板的点

1. **K = 100 是否合适？** 现在民间 1 两 = 国库 100 两。若觉得朝廷该更富/更穷，只改这一个常数。
2. **官俸 1.5 两/官/日 × 62 官**（国库尺度 9,300/日）。官是否太多（56 城养 62 官）？要不要按品级分俸？
3. **损耗率曲线**：6% 起、`压力/400` 递增、封顶 35%。这个斜率合不合适？
4. **贪墨比例 30%** 进官员私囊，其余 70% 视为「蒸发」。要不要调？
5. **赈灾 5,000/次** 与「拨不出」的后果（压力 +5、民心 +4）是否过轻/过重？
6. **关税城识别用正则**（`运河|码头|江南|淮|漕`）。若觉得太随意，应改为城市数据里带 `hasPort` 字段。
7. **商税 2%** 与城税的叠加是否会导致税基失真？
8. **产业收益率封顶 12%**、再投资 25%——是否会通胀过快？
